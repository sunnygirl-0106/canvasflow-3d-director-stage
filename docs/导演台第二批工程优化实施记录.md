## B2 模型与资源交付

原文件可通过 `git show 7717264:public/assets/figures/bodykun_male.glb`（female 同理）恢复；资产替换与 URL 改造分别提交。全量业务回归及跨修订姿势结果见本记录末尾验收。

### 性能基线方法

`npm run measure:performance` 每类场景运行 3 次：2 角色、36 人群众、两组共 72 人群众、200 几何道具、50 道具/149 轨道/6109 键。各场景带统一的节点拖动路径；群众场景同时测步态。记录文档资源准备至首帧、对象选择、90 次求值、40 个播放帧、30 次真实鼠标拖动、长任务、渲染调用/三角形及 GPU/JS 内存趋势。启动耗时包含测试 harness 的 networkidle 等待，不等同于真实用户首屏绘制指标；场景准备指标包含默认模型缓存的复用。首次选择在求值采样之后进行。主视口按需绘制，因此不报告静止 FPS。

导出采用默认场景、24 fps、1 秒视频，720p 和 1080p 各 3 次；输出帧数/字节和状态恢复均断言。GPU 资源重复选择必须稳定，拖动只提交一次，导出必须恢复文档/历史/时间和渲染锁。速度只有报告，没有人为 FPS 门槛。夜间/手动 `performance.yml` 独立运行，采用与功能验收相同的固定浏览器和中文字体。当前本地 Chrome 150 的 SwiftShader 结果不能外推为桌面 GPU 表现；JS heap 受 GC 和浏览器统计粒度影响，只看趋势。
