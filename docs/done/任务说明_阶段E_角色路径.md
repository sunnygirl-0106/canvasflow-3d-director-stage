# 任务说明 · 阶段 E · 角色路径：绘制、顶点编辑、视口可视化

> 读者：Claude Code 执行者。先读《交接文档_导演台重构.md》4.3、4.4、6 节，再读本文。
> 分支：阶段 D 合入主线后从主线开 `feat/path-tools`。
> 本阶段改的是**视口交互与 Inspector**；`src/anim/` 只允许新增一个纯函数模块 `pathGen.js`，求值语义不动。

## 1. 背景

路径是阶段 C 做好的数据（`paths[]`，Catmull-Rom + 时长 + 速度曲线），阶段 D 能在面板上改 start/duration，但路径本身只能在控制台里敲坐标。阶段 E 让人在视口里画出来、拖得动。竞品 liblib 的做法：蓝色曲线 + 球形顶点可拖，播放时角色自动切走路。

这一阶段的路径生成器（直线、环绕、走到）同时是阶段 F 运镜预设和阶段 H AI 生成的积木，所以放在 `src/anim/pathGen.js` 里做成纯函数，不依赖 DOM。

## 2. 要解决的问题

1. 视口里看得见路径：线、顶点、方向、起止；只对选中实体显示可编辑顶点。
2. 五种绘制方式（见 3.2），都落到同一份 `points[]`。
3. 顶点拖动 / 插入 / 删除，拖动中实时预览，松手一次撤销（沿用 D 的"操作结束才写入"）。
4. 画路径时不能和视口环绕冲突（左键被占用）。
5. 新建路径与已有 `pos` 轨道互斥（校验器拒绝）：新建前要问。
6. 路径起点和角色当前位置的关系：避免 t=0 时角色"跳"到路径起点。

## 3. 目标架构

### 3.1 文档不变

`paths[]` 形状、词汇表（speed/orient）都不变。生成器的参数**不进文档**，文档只存生成结果 `points`；重新生成 = 覆盖 points。

### 3.2 生成器 `src/anim/pathGen.js`（纯函数，输入输出都是文档口径的 `[x,y,z]`）

```
line(from, to)                                   → [from, to]
arc({ center, radius, startDeg, sweepDeg, y, segments=8 })   → 圆弧采样点（sweep 可负；|sweep|≥360 时 closed=true）
toward(from, target, { stopDistance=0.8 })       → [from, target 前 stopDistance 处]；from/target 距离 ≤ stopDistance 时返回 null
simplify(points, tolerance=0.05)                 → Douglas-Peucker 简化（手绘用）
defaultDuration(points, { speed=1.3, closed })   → 弧长 ÷ 速度，向上取 0.5 s 整，最短 1 s
```
`arc` 的 y 与 line/toward 的点 y 一律由调用方给（角色 = 地面高度 `scene.ground.height`，阶段 F 的机位再给高度）。

### 3.3 五种绘制方式（Dock「路径」工具，选中角色 / 道具 / 组时可用；AI 词汇表里对应 `points / freehand / line / arc / toward`，前两者 AI 不用）

| 方式 | 交互 | 结果 |
|---|---|---|
| **点击落点** `points` | 进入后逐次点击地面落点，`Enter` / 双击结束，`Esc` 取消，`Backspace` 退一点 | 首点 = 实体当前位置（自动），之后每点一个 |
| **手绘** `freehand` | 按住左键在地面上拖，松手结束 | 采样 → `simplify(0.05)`；首点替换为当前位置 |
| **直线** `line` | 点一下终点 | `line(当前位置, 终点)` |
| **环绕** `arc` | 点一下中心（可吸附到实体：悬停高亮、点中取其脚底/中心），Inspector 里改半径 / 起始角 / 扫过角度 | 半径与起始角默认由当前位置到中心算出，sweep 默认 180° |
| **走到** `toward` | 点一下目标实体（必须点中实体），或按住 ⇧ 点地面取点 | `toward(当前位置, 目标)`，停在 0.8 m 外；太近则 toast |

- 共同规则：新路径 `start = playback.time`（idle 时 0），`duration = defaultDuration(points)`，`speed='smooth'`，`orient='tangent'`；创建 = 一次撤销。
- **起点规则**：五种方式的首点都是实体当前位置（手动值 base，投到地面），所以 t=0 不跳。拖动首点后起点就不再跟随实体；Inspector 提供「起点对齐到当前位置」按钮。
- 绘制状态下：视口左键归绘制，环绕视角改用 ⌥拖 或右键拖（看现有 CameraRig 哪个空着，不要破坏现有习惯——不确定就问）；顶部显示操作提示条（"点击地面落点，回车结束，Esc 取消"）。
- 已有 `pos` 轨道时点「路径」：弹确认 toast「该对象已有位置关键帧，创建路径将删除它们」[删除并继续 / 取消]。
- 已有路径时点「路径」：弹「重新绘制将替换现有路径」[替换 / 取消]；替换保留原 start / speed / orient。
- 组：路径点 = 组轴心位置；成员照阶段 C 一起走。

### 3.4 视口可视化 `src/core/PathOverlay.js`

- 每条路径一条蓝色曲线（`--accent`，宽 2px；用 `Line2`/`LineMaterial` 做等宽线，three examples 自带）；曲线按 Catmull-Rom 采样 ≥ 64 段 / 米上限 2000 段，贴地抬高 1 cm 防 z-fighting。
- 顶点：球体半径 6 cm（随相机距离保持屏幕上约 10px，用 `onBeforeRender` 按距离缩放），默认白，悬停亮，选中 accent；起点标三角箭头，终点标方块；每隔 1 m 沿切线放一个小箭头示意朝向（`orient='keep'` 时不画箭头）。
- 只有选中实体的路径显示顶点和箭头；其它实体的路径只画细线（50% 透明）；时间轴折叠与否不影响。
- 播放头位置在路径上显示一个小亮点（随 'tick' 移动），让人知道角色现在走到哪。
- 命中测试走 `Raycaster`：顶点优先于线，线优先于实体（路径线可点选 → 选中实体并进入顶点编辑）。

### 3.5 顶点编辑（选中实体后直接在视口操作，不需要进"绘制"模式）

- 拖顶点：在路径 y 平面上投影拖动，拖动中只改 overlay 预览曲线（不写文档、不求值）；松手 `updatePath(id, { points })` 一次撤销。拖动开始时若正在播放则暂停（同 D 的 gizmo）。
- ⇧拖任意顶点 = 整条路径平移。
- 点击线段 = 在该处插入顶点（插在最近两顶点之间，点落在曲线上）。
- 选中顶点后 `Del` 删除（≥ 2 点才允许，否则 toast）；`Del` 的捕获顺序：选中键 > 选中顶点 > 实体（沿用 D 的捕获拦截方式）。
- 顶点拖动时 gizmo 隐藏，松手恢复；`Esc` 取消拖动回到原位。

### 3.6 Inspector 路径段（扩展阶段 D 的段）

- 新增：顶点数、总长（m）、平均速度（m/s，= 长度/duration，显示灰字；超 2.6 m/s 标"跑"）。
- 新增按钮：「反向」（points 倒序）、「起点对齐到当前位置」、「按步速重算时长」（下拉：慢走 0.8 / 走 1.3 / 快走 1.8 / 跑 3.5 m/s）、「删除路径」。
- `arc` 方式创建的路径额外显示半径 / 起始角 / 扫过角度三个输入（改动即重算 points；这三个参数存在**会话态** `app.pathMeta[pathId]`，不进文档；文档重载后退化为普通点集，编辑框消失——这是有意为之，写进已知问题）。
- 「路径」段头部加「新建路径 ▾」下拉 = 五种方式入口（和 Dock 按钮等价）。

## 4. 分步执行（每步一个 commit，报告改动文件、测试结果、截图路径）

1. **pathGen.js + 单元测试**：五个函数，node 直接跑的测试（不用 puppeteer），覆盖 arc 的负 sweep / 闭合、toward 的太近返回 null、simplify 的容差。
2. **PathOverlay 只读显示**：线、顶点、起止标记、方向箭头、播放亮点、选中/非选中样式；控制台加的路径能立即看到。
3. **点击落点 + 直线 + 走到**：Dock「路径」按钮与方式菜单、绘制状态机、提示条、Esc/Enter/Backspace、环绕视角改键、pos 轨道冲突确认、起点规则。
4. **手绘 + 环绕**：手绘采样与简化；环绕的中心吸附、Inspector 三参数、会话态 pathMeta。
5. **顶点编辑**：拖动 / ⇧平移 / 插入 / 删除 / Esc 取消，Del 捕获顺序。
6. **Inspector 路径段扩展 + 验收 + 文档**：selftest `path` 子命令；README；交接文档 3 阶段表、4.3 补路径起点规则、4.5 路径工具已定设计、5 代码地图、6 下一步（阶段 F）、已知问题；本文件移到 `docs/done/`。

## 5. 验收标准（selftest `path` 子命令，puppeteer 真实点击/拖拽，截图到 `test-output/path/`）

1. **点击落点**：选中角色（站在 (−1.1, 0, 0.2)），Dock「路径」→ 点击落点 → 视口点 3 个地面位置 → Enter：`paths[0].points.length === 4`，`points[0]` ≡ 角色当前位置（误差 < 1 mm），`start === 0`，duration = `defaultDuration` 的值；t=0 截图 ≡ 创建前截图（0%，不跳）。
2. **手绘**：拖一条约 4 m 的 S 形：简化后点数 ∈ [5, 40]，原采样点到简化曲线的最大偏差 < 5 cm。
3. **直线 / 走到**：直线 2 点；走到道具：终点到道具中心水平距离 = 0.8 ± 0.01 m，方向在连线上（偏差 < 1°）。
4. **环绕**：以道具为中心，半径由当前位置得出：所有点到中心距离 = 半径 ± 1 cm；Inspector 改 sweep 为 360 → `closed === true`。
5. **拖顶点**：把第 2 个顶点拖 1 m：`updatePath` 恰好调用一次、History 长度 +1；拖动中 `toJSON()` 不变；Esc 取消后 points 不变。⇧拖整体平移：所有点位移一致。
6. **插入 / 删除**：点线段中点 → 点数 +1 且新点在两邻点之间；选顶点 Del → 点数 −1；2 点时 Del 被拒绝（toast）。
7. **冲突**：有 pos 轨道的角色点「路径」→ 出现确认 toast；取消 → 文档不变；确认 → pos 轨道删除且路径创建，为一次撤销（⌘Z 后轨道恢复、路径消失）。
8. **绘制态不冲突**：绘制中在地面按下拖动 → 相机不转（导演视角 `editorView` 不变）。
9. **可视化**：截图：选中实体的路径（顶点 + 箭头 + 起止标记）、非选中（细线）、播放中（亮点位置与角色脚底水平距离 < 5 cm）。
10. **播放**：画完一条 6 m 路径直接 Space：角色沿线走路，t=duration 时停在终点（误差 < 1 cm）。
11. **往返**：含手绘路径的文档导出 → 导入 → 导出 ≡；导入后 overlay 立即显示。
12. 原有 e2e、doc、anim、tl、collide、lint 全过。
13. 产品侧手动验收截图：五种方式各一张、拖顶点中、插入顶点、Inspector 路径段。

## 6. 约束

- 不引入新依赖；等宽线用 three 自带的 `examples/jsm/lines/`。
- `src/anim/` 只新增 `pathGen.js`；`Timeline / PathTrack / Locomotion` 不动；碰了就跑 `selftest anim`。
- 路径的写操作只有 `addPath / updatePath / removePath` 三个入口；overlay 不持有文档状态，只响应 'change' 和 'tick'。
- 生成器参数不进文档（见 3.6），文档形状与词汇表不变；若执行中发现必须进文档，停下来问。
- 不做：机位路径与运镜（F）、路径吸附到其他路径、曲线张力调节、沿路径的速度分段。
- 说明没覆盖的决策：停下来列选项问。预计会碰到的：绘制态下环绕视角用哪个键；顶点球体在"机位视角"下是否显示（建议不显示）；组的路径点 y 取组轴心还是地面（建议地面）。
