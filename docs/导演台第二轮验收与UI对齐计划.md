## 3. P0：无框、全视口播放

### 行为规格

1. 播放前后中央视口DOM边界与尺寸相同；图像绘制覆盖整个中央视口，不留由固定输出比例产生的空边。禁止新增弹层、内嵌播放器、画中画或覆盖面板。
2. 点击播放仍取实际主机位；区别仅为相机画面开始运动、播放按钮变暂停、时间及播放头推进，必要的视角高亮更新。摄像机视角切换导致构图变化合理；**由框/留边/布局变化导致的二次缩放不合理**。
3. 暂停保持同样铺满的机位画面；停止、循环、重复进入退出均不闪出旧框或残余遮罩。用户在机位视角按播放，t=0前后静态构图应完全一致。
4. 导演视角手动播放头检查仍可用；默认播放看机位的既有决定不被参考1的状态推翻。
5. 网格、地面、角色名牌可见性不因“成片播放”突然改变；只隐藏机位模型、视锥、选中环、拖拽控件、路径点等编辑辅助物。不加全局变暗或失焦效果。

### 最小代码方案

- `App._applyFrame()`：解除普通播放与exportSize的强制绑定，播放时关闭frame的可见显示及其阴影，不是只关伪元素。退出后恢复用户显式选定的编辑取景框状态，不写场景ratio。
- `Stage.render()`：普通播放使用完整viewport与该viewport的aspect；清除本轮新增但不再需要的预览scissor分支/状态。若其他真实用途仍需该分支，明确调用者后保留，不留下无人使用的兼容分支。
- `CameraRig`：移除只服务于旧留边预览的previewFrame特殊计算；显式截图/导出取景机制保留。检查resize后有效机位projection更新。
- `ShotManager`、`VideoExporter`：导出比例仍有效，不能因取消播放框破坏输出尺寸。播放全视口和固定比例导出在aspect不同时不承诺边缘内容相同；导出面板现有比例/预览承担裁切说明。**同机位、同时间、同aspect**时才要求逐像素/构图等价。
- 保留现有clean-render配对、暂停与恢复机制，验证截图/导出嵌套退出后恢复正确viewport、scissor、aspect及名牌状态。
- `Labels/LabelSprites`：复用现有两套显示入口中的测量/样式，统一成白字、细暗描边或轻阴影、无白色气泡底；以屏幕视觉字号一致为目标，不另建第三套标签系统。默认角色名不要在播放瞬间变成巨大招牌。

第一轮director套件中“普通预览必为16:9或9:16”的断言属于旧需求，必须重写为“全视口”；保留对显式导出尺寸、相机解析和洁净嵌套的验证，不能直接删整段测试。

## 4. P1：三按钮工具坞＋AI输入胶囊

### 4.1 默认外观

两个相邻胶囊作为一组，位于**中央视口**水平中心，靠下且紧邻时间轴上缘，不以整个页面中心定位。工具坞不得因为AI状态切换而横向跳动。

左胶囊仅三个图标：**移动、截图、动画时间轴**，顺序固定。右胶囊：`＋`、占位文字“描述想搭建的场景”、圆形上箭头发送按钮。空闲态无“AI导演”大标题、模式标签排、模板卡片墙、长说明或模型配置表单。

以参考2显示为2048×1152的归一化画面为测量基准：工具坞约x=813～963、y=770～825，宽150、高55；AI框约x=972～1235、宽263、高55；间隔约9px，距时间轴顶边约5px。其整体中心约等于中央视口中心。实施前核对原图与设备像素比，不能把附件像素无脑当CSS像素。

圆角约半高；底色深灰，细灰描边；按钮透明底，选中按钮为独立灰色圆角块；图标视觉尺寸约22～24px、统一线宽1.6～1.8和圆角端点。沿用 `ui/icons.js` 的SVG体系，调整pointer/shot/timeline图形，不混emoji、文字符号与不同风格图标库。参考图标可优化清晰度，布局/尺寸/颜色/状态仍逐项对齐。

### 4.2 交互与原功能去向

| 原入口 | 新入口/行为 | 复用 |
| --- | --- | --- |
| 移动/旋转/缩放 | 第一个按钮默认移动；再次点或展开菜单选旋转/缩放，tooltip说明当前模式 | `setTransformMode`、现有transformMenu |
| 截图 | 第二按钮直接截图 | `shots.captureShot()` |
| 时间轴 | 第三按钮开合时间轴，展开时高亮，展开收起不丢播放头/缩放 | `toggleCollapsed()` |
| 添加角色/道具/机位 | 左侧对应分类入口 | Dock现有菜单构建与实体动作 |
| 路径 | 对象轨道“绘制轨迹”和右侧运动轨迹入口 | PathTool、现有pathModes |
| 全景 | 左侧图像入口或现有场景面板 | 原上传/历史流程 |
| 画幅比例 | 机位/截图设置内，使用原选项 | `setRatio` |
| 撤销/重做/导入导出/全屏 | 场景标题附近更多菜单，快捷键保留 | 原sceneMenu与动作 |
| AI设置/预制/历史 | AI的＋菜单或按需展开的小面板 | 现有AiPanel/agent/provider |

迁移入口要真实可达，不能只把原按钮CSS隐藏、留下锚定到隐藏元素的弹出菜单。迁移菜单锚点和事件注册，保持一次点击一次动作。

### 4.3 简洁AI的完整状态

- 空闲：常驻单行胶囊；可输入，空内容禁用发送。默认复用当前“修改当前场景”；通过＋选择生成新场景、参考图、预制、会话历史、设置。不要为了简洁偷偷清空已有场景。
- 编辑：输入最多自然长到2～3行，超过内部滚动；上浮扩展区域不推动舞台和时间轴。草稿跨焦点/展开收起保留。
- Enter发送，Shift+Enter换行；中文输入法组合态Enter不发送；输入空格/方向键/Delete不得触发播放、移帧或删实体。
- 生成中：发送按钮变取消/忙碌态，短文本提示；禁止重复提交。保留现有取消能力与原子应用。
- 成功：一句结果＋可用的撤销入口；详细操作/重试记录放按需展开的会话区，不能常驻技术日志。
- 失败：简短原因＋重试，保留草稿；无模型配置时提供设置入口，配置表单按需展开。
- ＋参考图：复用压缩/大小校验，缩略图可移除。预制只填草稿，不自动发起模型调用。生成模式替换场景沿用原有清空确认。
- 只改UI壳，不重写agent、校验、重试、事务和密钥存储；只保留一个草稿/忙碌状态来源和一个提交方法，避免新胶囊与旧抽屉各维护一套状态。

## 5. P1：左侧与左下角逐项对齐

### 5.1 页面骨架

参考2归一化2048×1152：左侧总宽约329（其中窄图标栏56），中央视口x=329～1718，右栏约330；标题行仅占左侧顶部，中央画面从顶部起；视角切换悬浮在中央上方。时间轴上缘y≈830、约占页面下方28%。

当前横跨整页56px header是明显差距。下一轮在 `index.html/style.css` 重排：左标题含关闭/标题/折叠，左侧窄图标栏＋场景列表；中央顶部浮动视角切换；右属性标题独立。右上导航球/重置入口在两种视角保持参考中的位置；机位视角下“重置”须定义为不修改场景机位数据的视图恢复，不能误写相机位置。

大屏按参考比例对齐，小屏设置可用最小宽度并允许侧栏折叠。不要只校准三按钮却保留完全不同的页面框架，也不要整体CSS transform缩放界面来假装像素对齐。

### 5.2 左下角播放控制

参考顺序：播放/暂停 → 秒表形辅助按钮 → 循环 → 当前秒数/总时长/s组合胶囊 → “＋新建轨道”或“－移除轨道”。当前demo是播放→秒数带斜线→循环→垃圾桶→更多，需调整。

- 当前时间/总时长分别在紧邻灰色区块，数字两位小数、等宽数字；去掉裸斜线式文本。
- 循环启用时灰色圆角背景，不是鲜艳蓝色按钮。
- 新建/移除必须有中文文案与上下文状态，不能只有不易理解的垃圾桶。新建沿用现有打键/添加轨道机制，提供属性选择；移除只删选中动画不删实体，一次撤销恢复。
- 秒表图标真实语义静态图不能确认：本轮可暂定映射既有“回到开头（Home）”，以tooltip明确；不得声称已验证竞品该按钮行为。不要新增计时器功能。
- 停止、自动打键、吸附、主机位选择、前后帧等保留在更多菜单与快捷键，更多入口低强调，不挤掉参考中的主操作。

### 5.3 轨道区及右侧工具

- 左名列约18.4%整页宽；参考2主行约38px高、条形约34px高，子行约38px。按统一尺度校准，当前30px行＋窄条需要调整。
- 未选中角色条为中性灰，主机位未选中可用低饱和灰绿；**选中条为饱满青色**，对应整行深青背景；不要所有对象一律青色。
- 主行显示折叠箭头、名称、右对齐青色“绘制轨迹”；下方属性子行有树形连接线、上一键/菱形/下一键、右对齐属性值；不要为无动画对象默认展开一排空“位置”。
- 相机子行按真实数据展示“位置”“焦点（注视：两人）”“视角（FOV）”；将lookAt约束呈现为可读焦点信息，不复制另一份约束数据，也不为凑截图伪造FOV关键帧。
- 非动画道具保留在场景清单，时间轴默认聚焦角色、机位和已有动画对象；道具创建动画后可见。折叠和过滤仅影响UI，不删文档对象。
- 播放头改为参考的浅色头标＋细白线，关键帧空心青色菱形，选中高亮；边界拖柄清晰但不能让仅展示的实体条假装可编辑动画长度。
- 右侧顺序：缩放滑条、折叠、帧率、白底深字导出按钮。把当前亮青色导出按钮改成参考风格；“适配全长”放合适的快捷动作/更多菜单，不抢主按钮位置。
- demo无画布回传实现时仍标“导出视频”，不伪造“到画布”功能；这是文案上的明确例外。

## 6. 精确对齐的方法与验收门槛

不接受只说“整体更像”。每个批次必须提供同尺寸截图与区域对照：

1. 原始参考图和测试截图统一到相同尺寸/缩放条件，先对齐页面边界，再比较侧栏、时间轴、工具坞、AI输入、左下角五个区域；参考3是裁切图，不能拿它的整页高度推布局。
2. 在1920×1080目标基准下，主要边界、按钮中心、间距与换算后的参考误差目标≤2 CSS px；圆角、线宽、字号、背景色逐项记录实际值。1440×900和1440×810再验响应式，不把大屏数值机械压进小屏。
3. UI静态部分做裁区叠图/差异图；3D内容因模型、光照、姿势不同单独检查，不用全图像素差掩盖UI误差。文字抗锯齿不作为布局偏差。图标允许精修，按钮外框与对齐不变。
4. 同一场景、同一相机、同一时间的“播放前/播放中/暂停”对比：框、阴影、留边均无；侧栏/工具坞/AI/时间轴外框不移动，状态图标与时间可变。
5. 双场景：A为匹配参考的一坐一站；B为用户的男女同坐长椅。固化测试JSON，避免每次随机模型生成导致构图无法比较；另外真实自然语言生成只做独立集成验收，不混入UI像素测试。
6. 辅助检查：图标hover/选中/禁用/键盘focus可辨；发送、停止、截图、移除都有aria-label或可读名称；点击区≥32px，窄时不能互相遮挡。

## 7. 改动顺序与代码质量约束

**批次A：无框播放修正。** 仅改预览viewport/框/名牌与相关回归断言；验director、cam、export、截图及resize。先解决用户最直接的不适。

**批次B：页面骨架＋三按钮＋AI胶囊。** 复用Dock菜单能力与AiPanel逻辑；先做所有原功能的新入口映射，再删除旧入口。验快捷键、中文输入、草稿、取消/失败、上传和配置状态。

**批次C：时间轴细节。** 调整颜色、密度、树形结构、秒数胶囊及新建/移除；复用时间坐标/吸附/轨道事务，不改动画计算。

每批提交可独立审查。禁止新增UI框架、图标包、大型状态管理层、重复播放器、第二份AI控制器；禁止持续扩大App内的临时分支。抽取组件仅因明确职责边界，不为改三个按钮造通用插件系统。删除旧预览分支时检查所有调用者和测试，不保留死代码。
