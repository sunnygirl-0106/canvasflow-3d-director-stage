# 第三轮：视觉差异与默认构图修正

> 2026-10-22后续规格：[第四轮首屏与轨迹交互优化技术方案](导演台第四轮首屏与轨迹交互优化技术方案.md)。最新要求保留双人及默认轨迹，首屏时间轴关闭、正面轻俯视，补六导航、延伸视锥、胶囊预制和路径类型菜单。冲突条款以第四轮为准，本轮全UI颜色规范继续有效。

本轮依据：用户提供的demo/竞品两张截图及2026-10-21当前工作区源码。只制定修正规格，未改产品代码、未重跑本轮全套测试。第二轮测试结果不能代表后续工作区实现。本文件是第二轮计划的补充；预制场景功能保留。

**执行优先级：本文件为最新交接入口。用户追加要求是所有UI尽量对齐，包括颜色，而非仅改相机与几个按钮。第六至第十节为全量实施清单；与前两轮冲突时以本文件为准，未冲突的功能兼容与质量约束继续有效。**

## 一、为什么仍然不像

1. **比较状态不一致。** demo为机位视角、选中摄影机；竞品画面可见场景内相机及轨迹，右栏是场景参数，属于导演观察状态。右侧面板内容不应为了截图被强制改成相同；需先在同视角、同选择、同时间下比较。
2. **构图是当前最大差异。** demo两人分别贴近左右边缘，中央空洞，地面网格接近水平消失点；竞品采用斜上方观察，主体更集中，地面空间关系清楚。视觉问题先于按钮微调。
3. **默认参数来自三个不同入口。** `defaultScene.js` 用front_mid，初始机位约0.96m高；`CameraRig.frameAll()`保留当前观察方向，并不建立统一斜俯视；AI预制“迎面相遇”明确写了相距8m、正面8m、高1.8m。只改默认seed无法改善后两种场景。
4. **颜色与渲染差异。** `CHARACTER_COLOR`统一绿色，图中男女均为绿；参考用蓝/红区分。当前地面偏暗、网格在远处聚成细密条纹，人物与场景更像调试画面。
5. **AI只模仿了空闲态。** 当前AiPanel把“已应用N项修改＋撤销”作为独立常驻状态块；参考是与输入框一体的“历史对话”头部和继续描述输入，状态结构不同。
6. **时间轴还暴露底层实现。** 主条下面再叠路径区间条，色块重复；参考通过位置/旋转/姿态/焦点/视角等属性行表达动画。不能靠把“路径”两字改成“位置”解决。
7. **细节未统一。** demo右栏常驻红色时间轴提示、属性tab下划线、蓝色滑条、独立主机位蓝标签，与参考的低强调提示、灰色胶囊tab、青色滑条不同；左侧第一图标也仍是四格而非图层。参考的右侧当前为场景面板，摄影机tab样式应对照第二轮参考2验证。

## 二、第一优先级：三类相机入口分别处理

### A. 导演观察视角

- 建议观察方位：水平偏转25°～35°、向下观察20°～30°，围绕主要角色/道具的主体中心取景。此为待视觉校准的建议，不是竞品已知参数。
- 主体集合在中央视口中保留约10%～15%安全边距，避免人物贴边、被底部AI条遮挡。主角高度建议先在视口25%～40%区间调试，不继续把所有场景强行套入上一轮单人20%～25%的规则。
- 新建场景、生成新场景完成后建立一致的导演总览；修改已有场景保留用户视角。生成后是否切视角应由明确的新建流程决定，不由残留cameraView状态随机决定。点击播放继续进入主机位。
- 复用 `CameraRig` 包围盒与取景计算，增加有明确用途的初始方位选项或总览入口；不要改变显式“对准主体”保持用户方向的既有意义。
- fit主要角色与近景道具；远处建筑/机位路径不应把主角缩成点。默认reset回该场景总览，不回一个固定世界坐标。

### B. 默认拍摄机位

- 新默认单人拍摄机位建议高1.45～1.65m、朝胸腹之间的构图中心，轻微俯拍，完整全身。相机FOV先以45°～50°试拍，结合主体包围盒求距离；不是统一把FOV调大就结束。
- `defaultScene.js`不要继续将front_mid的身体中心高度直接当作新默认机位高度；可以为默认场景明确参数，但不偷偷改掉所有现有景别预设。
- 多人机位按主体组边界拟合实际视口；优先保证全身、两侧留白和人物关系。相机朝向可由lookAt计算，禁止同时维护一份手写Euler和另一份冲突的lookAt。
- 图中机位Y=1.80、注视Y≈0.88、Z≈8.02，按显示坐标估计向下俯角约6.5°；“低”的主要感受来自近乎水平观察。与竞品导演俯视不能直接以相机Y作比较。

### C. AI与预制构图

- 保留预制功能，修订“迎面相遇”的构图默认：未明确要求远距离时，建议初始相距4～5m、终点约1.2～1.8m，双人占画面中央约60%～75%宽；具体数值须在动作全程采样验证。
- 用户显式要求8m则保留8m，不为好看静默缩小站位；通过相机布局和安全边距容纳轨迹。电影构图建议不能覆盖用户场景语义。
- `ai/presets.js`、`ai/prompt.js`与实际机位生成约定一致；默认策略仅补缺省值，保护用户指定位置/FOV/颜色。
- 不只靠prompt保证“全程入镜”。对预制样例在0%、25%、50%、75%、100%检查两个人物边界；生成通用场景时先提供可解释的构图检查/修正范围，避免无限循环自动挪相机。
- 拍摄构图和导演观察构图独立，不把编辑视角序列化成相机运动，不在每帧重新fit造成镜头抖动。

## 三、第二优先级：把不同状态的UI补齐

### AI输入区

- 保留空闲“三按钮＋输入胶囊”。生成成功后进入参考的继续对话态：上方窄“历史对话 ＞”条与下方输入框共用一个容器，左侧返回按钮退出继续对话态。
- “已应用N项”移入历史详情，成功只短暂轻提示；撤销在历史当前轮可达，不额外常驻一块大卡片。
- 展开/继续态按参考加宽，底部位置固定；折叠态回到三按钮组合，草稿不丢。输入焦点、取消、失败重试保持现有逻辑。
- 使用现有AiPanel状态与agent.turns；不要新建平行的会话存储或第二套提交方法。

### 时间轴

- 主行负责对象时间范围，位置子行负责位置动画；不默认显示第二条整行青色“路径胶囊”。
- 路径驱动的位置以“位置（路径驱动）”及细线显示，提供进入路径编辑的入口；位置关键帧与路径顶点不是一种数据，不伪造菱形关键帧。路径区间编辑移到展开的轨迹编辑层，保留真实能力。
- 真实旋转、FOV关键帧按属性显示；lookAt显示为“焦点/注视目标”。没有相应动画就不为凑截图生成数据。
- 默认只展开选中对象，其他对象保留主行；用户手动折叠选择记在会话态。主行高亮不要把所有子行都填成同强度的大色块。
- 空心关键帧、细属性线、灰色未选中主条、浅灰播放头和青色选中状态统一；保持原拖拽、吸附、缩放、撤销模型。

### 侧栏与图标

- 摄影机面板分属性/运动轨迹/截图，复用当前Inspector各区块；属性内保持名称、机位切换、变换、目标/FOV的清晰顺序，画幅放截图设置。
- 删除常驻红色“时间轴激活中”条，改为属性附近低强调状态说明；实际编辑被阻止时才提示原因。普通暂停不是错误。
- 统一tab胶囊、青色滑条、字段背景、标题与间距；导航球使用圆点/短轴的视觉形式，保留已有方向计算。
- 左侧图层图标、各分类图标、底部移动/截图/时间轴统一描边、视觉尺寸与留白；继续使用icons.js，不引入整套新图标依赖。
- 预制入口保留。右侧面板内容由选中对象决定，不为静态截图清空选择；主机位名称提示移入不占额外垂直空间的低强调位置。

## 四、第三优先级：场景视觉

- 新建角色默认按明确调色板区分，首两人建议蓝/红；不是按性别强制着色。显式颜色、旧文档颜色不变；缺省颜色规则在公共实体创建入口统一，人工添加与AI一致。
- 先校准相机再调整地面；不要用把scene.scale改成300%来复制参考。场景缩放会改变空间关系，截图中的300%不是全局默认依据。
- 地面略提亮、网格低对比且远处淡出，避免地平线密集条纹；保留坐标操作辨识度。光照/材质只做小范围参数校准，不替换模型、骨骼或动画。

## 五、验收与实施范围

按“构图→AI状态与时间轴信息→视觉细节”三个可独立审查批次实施。预制功能和现有无框播放保留。不得借机重写播放器、文档schema、AI执行链或骨骼系统。

必须建立四组同状态截图：①新建单人导演总览；②同场景机位视角；③同一双人场景同一时间的导演/机位两图；④AI成功后的继续对话态。每组记录camera position/target/FOV、viewport大小与选中对象。不能再拿两种视角的不同场景宣称像素对齐。

在1440×900和1920×1080检查人物边界、遮挡、重置、resize；多人预制全过程采样不裁头脚。新增纯几何边界测试仅覆盖实际构图算法，UI真实交互验证生成完成/修改场景/播放/暂停/历史/撤销。最后重跑check、build、受影响E2E与全套回归；未实测的新实现不能沿用前一轮“全部通过”结论。

## 七、颜色、字体与控件规范

补充待采样项：普通灰色实体条、描边、分割线、青色滑条、滚动条、hover/focus/disabled。实施者先从可见原图平坦区域取样；截图未显示的状态按邻近灰阶设计并标注来源，不能伪造精确色值。

**实现方式：**先盘点style.css/timeline.css/内联SVG中的色值，以少量语义CSS变量统一；旧的 `--accent:#3b82f6` 不应继续支配普通控件。不要简单全局替换蓝色：世界Z轴、真实角色色、错误提示有独立含义。timeline目前以red/purple等旧名字承载青色的变量应按实际用途整理，删除重复覆盖，不再在文件末尾不断补覆盖样式。

### 7.2 字体、尺寸与状态

- 保留中文系统字体栈，按参考层级校准字重；正文不普遍加粗，标题与选中状态有区别。秒数/坐标用tabular-nums，避免播放时宽度跳动。
- 具体字号/行高须与统一参考尺度共同标定，禁止为塞进布局任意缩小个别字段。右栏标签与控件、组间距、行内XYZ间距分别使用统一间距值。
- 图标统一24单位viewBox、约1.6～1.8描边，按按钮大小输出；光学居中与点击区域分开。禁止文字箭头/emoji混入SVG按钮。
- 控件圆角按用途统一：整体胶囊半高圆角、字段中圆角、小按钮小圆角；不能所有容器一个大圆角。
- 每类交互检查默认、hover、active/selected、disabled、focus-visible；错误、loading为额外状态。键盘focus必须可见，不能为了截图一致删outline却不给替代。
- 无参考的tooltip/弹层沿用相同灰阶、描边、字体与间距，不追加高饱和蓝紫渐变、重阴影或动画。

## 九、最终验收清单与对齐标准

### 9.1 必交截图状态

- 新建默认场景：导演视角＋角色属性；同场景机位视角＋摄影机属性。
- 无选中对象：场景面板展开到背景/全景球区域。
- 角色属性、姿势、运动轨迹三个tab；摄影机属性、运动轨迹、截图三个tab。
- 双人场景：导演观察、播放中、暂停，记录相机和播放时间；未选中与选中主机位轨道各一张。
- AI：空闲、正在输入、生成中、成功后的继续对话、历史展开、失败重试、设置、预制选择。
- 菜单/弹层：变换、添加角色、添加机位、路径、右键、导出、截图历史、工具提示。
- 时间轴：折叠、展开、逐帧缩放、横向滚动到末尾、纵向滚动及选中关键帧。
- 加载失败/重试、无机位提示等关键非正常状态，不能只交一张漂亮的默认截图。

### 9.2 视觉验收

1. 1920×1080为主对比尺寸；1440×900与1440×810验响应式。原图按等比例映射，先核对裁切/DPR，不把3840物理像素直接当CSS像素。
2. 同尺寸下五大区域边界、控件中心与关键间距偏差目标≤2 CSS px；字体抗锯齿/3D渲染不使用同一像素阈值判断。折叠布局另有预期，不拿展开图比较。
3. 平坦UI区域的目标RGB以第七节为基准，截图中位颜色每通道偏差目标≤3；透明叠加区域比较最终屏幕色，不硬要求底层CSS值相等。抗锯齿边缘、网格、阴影和3D材质排除该阈值。
4. 输出左栏、右栏、工具坞/AI、时间轴左控制、轨道区的裁区并排或半透明叠图，明确已对齐/仍有差异/缺参考三类结果。不能只写“看起来更像”。
5. 用户允许图标更精致、保留预制入口；demo没有画布回传时保留“导出视频”文案。这些明确例外之外，有参考的UI不要自行换风格。
6. 性能与交互检查：播放中不重建整个Inspector/时间轴DOM，图标与数值更新不引发布局跳动；输入框中文组合态不误触快捷键，菜单不被overflow截掉。

### 9.3 功能质量门禁

执行 `npm run check`、`npm run build`、`npm run test:e2e:all`。对新构图/AI继续态/面板tab补有意义的测试；明确被新规格替换的旧断言，保留其他覆盖。报告实际通过/失败/未运行，不沿用上一轮统计。再次核查旧文件导入、用户显式机位参数、角色颜色、撤销、截图、视频帧数和无框播放均未回归。
