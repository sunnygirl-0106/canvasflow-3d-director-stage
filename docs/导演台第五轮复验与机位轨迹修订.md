## 2 统一默认构图

### 产品决策

默认主机位和导演相机必须使用同一份构图：

| 参数 | 最新值 |
| --- | --- |
| 位置 | [0,2.2,10] |
| 注视坐标 | [0,-0.71,0] |
| FOV | 50° |
| Roll | 0° |
| 跟随 | 无 |

`-0.71`来自用户手调，本次试调确认会使人物在画面中上移。它是画面构图用的观察目标，位于地面下方，不等于A/B的胸口或身体中心。不要为了把目标描述成“对准人物”而移动人物世界坐标。

竞品截图的Y=1.2已被用户最新校准值覆盖。采用本项目 `aimAt()` 求方向，本组参数的下俯角约16.2°，不能继续断言5.71°，也不能照抄竞品的Y旋转180°。把位置、目标和旋转混用为不一致的三套数据，会再次偏离画面。

### 修改入口

1. `src/core/framing.js`：删除本轮错误的默认“双轨构图”分支，由一份默认位置、目标和FOV生成两视角初始化结果。保留通用 `fitBounds()`、手动对准主体等功能，不再自动套用“人物上移5%”二次偏置。
2. `src/app/defaultScene.js`：用同一份数据生成主机位和初始 `editorView`。导演相机不再独立按人物包围盒推另一个距离。
3. `src/core/Stage.js`、`src/app/DocumentController.js`：确保导演投影参数实际变为50°并更新投影矩阵；仅改变位置和target不够。
4. `src/core/CameraRig.js`：初始home／reset恢复位置、目标和FOV；目前 `_home` 只存pos/target，必须补齐必要投影状态。

### 保存与兼容

优先在现有 `meta.editorView` 内增加可选 `fov`，不要另存一套“导演机位”实体。同步schema允许字段、校验、导出、载入和home；新默认存50°，旧文件缺失时按旧导演相机40°恢复，不能全局换默认后让旧构图悄悄改变。

是否提升文档版本按既有迁移规则处理；不要要求旧文件必须有新字段。切换到场景中其他用户机位或加载旧文件时，不能强行覆盖其参数为默认值。

### 同步边界

- 首次进入和未主动环绕时，导演视角与默认主机位构图一致；修改该机位注视点／位置／FOV后仍保持一致。
- 用户主动环绕或平移导演相机后，观察视角允许独立；该动作不能修改主机位。使用一个编辑会话状态记录是否已主动脱离，不持久化额外相机副本，也不靠每帧比较浮点位置猜测意图。
- 视角切换本身不算主动环绕；若仍处于默认同步状态，切过去再切回来应无构图跳动。
- 重置默认观察视角时，从默认主机位当前构图恢复并重新进入同步状态；用户调整后的-0.71不能因reset回到旧1.2。
- 播放、截图、视频导出仍使用真实机位；导演视角辅助线与机位干净画面可以不同，但角色投影必须一致。窗口／画幅的有效aspect策略必须相同，不能用视觉近似代替投影一致。

## 3 首屏辅助物与操作Gizmo

源码链路是 `main.js initialize()` 默认 `select(角色A)` → `App._reflectPrimary()` → `gizmo.attach()` → `gizmoShouldShow()` 允许显示。不是因默认机位实体被自动选中。

### 修改要求

- 首屏没有角色或机位的XYZ拖拽箭头、旋转圆环、缩放手柄。可保留角色A属性面板，但要区分“程序默认选择”与“用户明确进行变换操作”。
- 在现有选择／显隐策略中增加一个明确的会话编辑状态，初始化选择不激活变换；用户主动选择对象或点击移动／旋转／缩放工具后才激活。不要用延时器在首帧后偷偷隐藏，避免闪现。
- `gizmoShouldShow()` 统一判断，加载、恢复、播放停止、截图结束、resize等路径都应遵守；不能初始化只调用一次hide，随后另一个事件又把它打开。
- 隐藏时禁用拾取与交互，不能让不可见手柄抢走拖动画布的事件。已有 `TransformGizmo.setVisible()` 会同步enabled，应复用。
- 默认机位的机身、标签和近端小框不显示；最多保留低透明度的真实视锥侧边细线。`CameraHelper` 的小框不是TransformControls，需单独简化可视化几何／显隐策略。
- 右上角的方向导航属于视角导航，不是对象操作Gizmo，保持可用。显式编辑机位后可出现机位手柄，退出编辑按统一策略恢复。

### 验收

冷启动不点击任何对象，连续检查首帧到加载完成均无操作Gizmo；普通选择／切换属性不会因后台事件产生闪现。用户明确选对象后可拖动，松手可撤销；取消选择、播放、截图／导出时隐藏。全程保留正常的方向导航和需要的细线。

## 4 新绘制轨迹默认固定10秒

### 根因

`PathTool._commit()` 传入 `start:0`，没有传duration。公共 `doc/edit.js setPath()` 因而按 `defaultDuration(points,{speed:paceFor(...)})` 自动估算；第五轮又把默认步速提高到1.44 m/s，短路径自然计算成约5秒。这与用户最新的固定时长要求不符。

### 新规则

| 操作 | 时长行为 |
| --- | --- |
| 用户新绘制路径 | start=0，duration=10 |
| 用户通过绘制工具重绘 | 默认重置为0～10秒，不沿用之前自动得到的5.1秒 |
| 插点、移动节点、编辑路径形状 | 保留现有start和duration |
| 用户输入时长、拖动条形范围 | 尊重明确设置的值 |
| 用户选择按步速调整 | 才调用defaultDuration |
| 载入旧文件／撤销重做 | 保留原数据，不自动迁移成10秒 |
| AI／其他调用显式指定时长 | 尊重显式值；不能被UI默认覆盖 |

适用范围：所有UI绘制入口、角色／群众／道具／机位，圆环、直线、矩形、铅笔、钢笔以及沿用绘制流程的走到／推到。独立运镜预设若有明确段时长，不属于无参数的默认绘制。

### 实施方式

在既有公共绘制提交入口统一传入10秒，而不是每种绘制模式硬编码一次。不更改有明确时长的调用；让 `defaultDuration()` 继续服务按步速调整和已有显式业务。

场景总长小于10秒时，在同一个 `Store.transact()` 中先延长到10秒再提交路径；否则 `fitPathToDuration()` 会将新路径重新裁成5秒。场景总长30秒时新路径仍为10秒，不能直接把总时长当默认路径时长。一次绘制仅一步撤销，撤销同时恢复原总时长。

时间轴长条、Inspector时长、结束节点和提示文字必须都显示实际10秒，不能只改面板文本。新建、重绘的提示也不再声称“已按步速适配”。

保留当前1.32周期/秒的迈步频率，不调整全局播放速度。固定路径长度和10秒时长后，平均位移速度由两者决定；不能同时要求任意长度路径均以1.44 m/s行走。较快步频与10秒时序独立处理，短路径需检查小步／滑步表现。
