# 第四轮：首屏、预制场景与轨迹交互优化技术方案

日期：2026-10-22。代码核查基线：`2d60436`；本轮只编写方案并保存参考，不修改产品代码。本文件是最新交接入口；与前几轮冲突时以本文件为准，其余全UI颜色、代码质量、无框播放要求继续有效。

## 1. 本轮明确决策

1. **保留一男一女、一个主机位及用户认可的默认角色轨迹。** 不再执行早期“一机位一人偶、空动画”的要求。未播放时静止在初始站位，不自动播放。
2. 首次进入的布局以[参考1：首屏](references/director-round4-initial.png)为准：导演视角、角色属性、时间轴关闭、底部三按钮与AI胶囊。时间轴打开后以[参考2](references/director-round4-timeline.png)为准。
3. 左侧主导航严格按：**场景、添加角色、添加机位、全景图、选择画幅比例、识图导入**。已有道具等能力保留，调整入口而非删除。
4. 预制场景融入底部AI输入，在胶囊上方轻量展开；不再用突兀的大弹窗。
5. 默认时间轴采用灰色低强调轨道，保留实际动画数据；不因选中了角色就铺满鲜艳蓝色长条。
6. “绘制轨迹”先选择类型，再开始绘制；对齐[参考3：路径菜单](references/director-round4-path-menu.png)的圆环、直线、矩形、铅笔、钢笔五项，并保留现有走到/推到能力。
7. 角色周围的细线是**三维机位视锥辅助线**，导演视角可见；播放时仍是无框、无辅助线的全视口机位画面。这与此前移除二维播放取景框不冲突。

## 3. 首屏比例与默认双人场景

### 3.1 布局状态

- 新用户首次进入：导演视角、时间轴完全关闭、默认选择男角色（或保留已确认的现有主选角色），右侧显示属性；不自动弹AI、预制、历史、帮助。
- 左场景树建议显示机位1、男角色、女角色；显示顺序由UI排序决定，不为了排序重排持久化实体或依赖实体数组索引。
- 时间轴按钮开启后显示三条对象主行及真实动画；收起后让出全部高度，工具坞与AI随视口底边移动。用户主动开合偏好可持久化，已有偏好不强制覆盖。
- 时间轴/侧栏resize更新投影和视锥，不重新摆人物或修改机位位置，不在每次resize调用fit。首屏关闭和开启是两种参考状态，不能继续强制26%高度常驻。

### 3.2 首屏构图标定

参考1缩放至2048×1120后：中央视口约x=329～1718；人物头约y=471、脚约y=691；身体高度约视口20%，脚底约62%高度；地面后缘约y=510。这组数值是首屏截图估读，**覆盖早期“脚底80%～84%”的默认要求**。参考2开启时间轴后上缘约y=900，人物屏幕位置基本稳定；不要求所有窗口尺寸逐像素维持其绝对位置，但禁止自动fit造成明显跳近跳远。

双人适配方案：两人围绕场景中心并排、全身入镜，保持同一地面、相近深度；建议初始中心间距1.2～1.6m、群组水平中心在视口中心、单人高度约18%～22%，不将双人横向跨度撑满视口。上述是无现有站位可复用时的建议基线，不覆盖用户已确认的站位。

初始导演观察方位先从正前方、水平偏转0°～5°、俯角5°～12°试调，以投影结果为验收；通用“总览场景”保留原斜俯能力。用已有fitBounds加明确的初始direction/occupancy/target偏置完成，不再造另一套取景算法。视口地面后缘还受地面范围与雾影响，不能把它直接认成精确地平线并反推唯一相机高度。

主拍摄机位复用当前48° FOV、约1.55m高度作为试调起点，保证两人和默认轨迹合理范围内可见；参数是项目建议，不是竞品测量值。先稳定默认站位/轨迹，再共同校准拍摄机位与导演相机，记录position/target/FOV/aspect。

### 3.3 双人/默认轨迹的兼容约束

- 若实际运行版已有双人及路径，导出其默认场景作为回归fixture，保持轨迹语义、时长和动作；本轮优先只改展示。
- 若当前分支确实没有：创建男/女各一、一个主机位、10s/30fps，两条互不交叉的简单短直线路径作为建议默认（例如各沿相同方向移动约0.8m）；起点等于角色初始位置，不自动加相机运镜。将这一补建明确写入交付说明，不能冒充原设计。
- 首屏视口不铺满两条路径控制点：默认隐藏未进入编辑的路径控制点，选中“编辑轨迹”后再显示；不删除路径。
- 不把双人seed写进createEmptyDocument；导入、恢复、AI清空均不自动补人/补轨迹。初始化一次原子发布并建立历史起点，不污染旧自动存档。

## 4. 机位视锥线：真实、细、低对比

### 4.1 解释与证据边界

参考中围绕人物的边线可约束机位方向、视锥截面与主体关系，但单张二维截图不能唯一解出相机距离/FOV/导演视角；必须通过真实投影匹配。禁止在画布上画固定矩形来假装视锥。

### 4.2 实现规格

- 保留CameraEntity已有真实cam、可视化_viz、helper与清理机制。扩展现有helper，不创建另一份相机系统。
- 可视化长度按机位至主体注视区域的前向深度推导，加小幅余量并设合理上下限；使用机位局部前向投影距离，处理主体在背面、空目标、极近距离。无目标时用有限缺省长度，不能等于far=1000。
- `_viz`使用真实cam的FOV、aspect和世界姿态；显示截面位于主体附近。画幅auto时随实际视口，显式画幅时明确按该画幅的取景锥同步；禁止在helper刷新里改变真实cam投影参数。
- 线条约1px视觉粗细，低饱和蓝灰、建议透明度0.15～0.3起调；无发光粗线、无填充面。参考线与网格应有轻微层次差，避免遮住人物。
- 如果CameraHelper默认中心线/额外标记过多，只简化显示几何，保留从真实投影导出的边；不为每帧重建geometry/material。
- 默认导演视角显示主机位视锥，即使当前选中角色也可见；其他机位按选中/当前机位策略显示，防止多机位叠成线团。用户隐藏机位时尊重显隐。
- 播放、机位视角、截图、视频导出隐藏视锥；停止回导演视角恢复。嵌套clean-render沿用现有机制，无新全局显隐标志。
- 机位移动、FOV/比例修改、窗口resize、场景缩放、路径求值后视锥同步；仅几何相关值变化时更新投影，位姿同步复用现有beforeRender流程。

验收：改变FOV时视锥截面宽度符合`2*d*tan(FOV/2)*aspect`，旋转/平移跟随真实机位；隐藏与恢复不改文档、近远裁切或导出尺寸。截面与两人位置关系可解释，不能只靠看起来像框。

## 6. 预制场景与AI胶囊融合

### 6.1 推荐交互

空闲态保持参考的三按钮＋AI输入；AI的＋菜单第一项“预制场景”。可保留左侧现有预制快捷入口，但两处都调用同一`openPresets()`，最终呈现在胶囊旁，而非两套界面。

打开后，胶囊上方出现同宽或轻度加宽的**预制托盘**：一行标题“选个场景开始”＋关闭，下面两列紧凑文字卡片，首屏最多4项，更多在托盘内滚动。建议桌面宽约400～440px、高约180～220px，窄视口限制在可用宽度内；这是轻量创新规格，不冒称竞品相同尺寸。

托盘与输入共用一个定位容器/描边风格，向上展开，不遮罩全页、不居中弹窗、不挤动舞台和时间轴。设置、历史、预制互斥展开；不将三种内容堆成大抽屉。

点预制：填入原预制prompt、明确生成模式，自动收起托盘并聚焦输入；**不自动发送、不修改场景**。用户可改词再发送；已有场景替换仍遵循原确认流程。若草稿非空，显示托盘内轻量“替换草稿”确认，取消保持草稿；不要另起modal。

### 6.2 完整状态

- 再次点预制入口或Esc收起，草稿保留；点外部关闭不误触舞台绘制。
- 生成中预制切换禁用或明确提示先取消，取消按钮始终可达；不会重复提交。
- 选预制与选参考图的模式切换要显式处理附件，不能悄悄带旧图发送新场景。
- 生成成功继续沿用历史对话/继续描述态；失败保留prompt并就地重试，不自动重新弹托盘。
- 支持键盘导航、焦点返回、中文输入法；托盘内Space不启动播放。
- 复用AiPanel草稿、SCENE_PRESETS、agent.busy、send和turns；以一个展开面板状态替代相互冲突的browsePresets/showHistory/showSettings组合（只在本轮确有冲突时小范围整理）。不新增预制执行器或独立历史。

## 7. 时间轴：保留默认轨迹，降低默认视觉强度

- 默认关闭；打开默认显示男角色、女角色、主机位三个主行。不能为了匹配参考只剩主机位就把两条真实轨迹隐藏到找不到。
- 未选中轨道为深灰/中灰，主机位可低饱和灰绿；presence仅低对比存在范围。角色被选中只突出行名/细边或浅底，**不自动把整段0～10s染成高饱和青色**。
- 饱和青色仅用于明确选中的可编辑动画范围/关键帧或实际拖拽反馈；不能把不可编辑的存在条伪装成可拖片段。若没有独立范围选择语义，不为了用青色新建一套选择模型。
- 默认路径用细位置线和简短“已设轨迹”状态表达；主行折叠，用户展开才显示位置/焦点/FOV等真实子行。路径端点不是位置关键帧，tooltip与可编辑行为必须区分。
- 选中对象与展开轨道解耦：首屏选中男角色，不意味着一开时间轴就展开全部动画。用户主动展开后保持会话状态。
- 沿用第三轮实测中性灰、白色播放头、青色细节点、灰色滚动条；去除任何残余默认整条亮蓝。时间仍为10.00s/30帧每秒，不迁移或缩短路径数据。
- 当前偏好键兼容：无偏好才采用新关闭默认；用户已有展开偏好继续有效。若调整collapsed从41px到0，需要同时修正弹出菜单定位、快捷键与尺寸观察，避免隐藏面板仍拦截指针。

## 8. 绘制轨迹：先选择类型，再进入工具

### 8.1 菜单与操作顺序

点击某行“绘制轨迹”时，仅在按钮上方打开约180～200px宽的菜单；空间不足自动翻转/约束到窗口，避免被timeline overflow裁掉。菜单记录该行实体ID，不能到点击菜单项时再用可能已变化的app.selected作为目标。

菜单前五项顺序和文案：圆环路径、直线路径、矩形路径、铅笔路径、钢笔路径；细描边圆/横线/矩形/铅笔/钢笔图标。分割线后可保留“走到目标”（机位为“推到目标”）。有路径时增加“编辑现有轨迹”，复用PathEditor。

点击类型后：校验实体仍存在→暂停播放→切导演视角→选中目标→通过统一PathTool请求进入。弹菜单、hover、按Esc本身不得暂停播放、切视角或写文档。用户从播放器中开始绘图时需恢复编辑辅助物，取消后有明确的编辑状态。

已有轨迹/位置轨道的替换确认沿用现有request逻辑；完成绘制时原子替换并记一步撤销，Esc/画不成形/实体删除不损坏原动画。不能先删旧路径再让用户画。

### 8.2 五种模式的实现映射

| 显示项 | 实现 | 本轮要求 |
| --- | --- | --- |
| 圆环路径 | 复用arc生成器，指定360°与closed | 当前180°不是圆环；首点等于对象当前位置，点击中心决定半径，半径太小拒绝；原半环绕运镜预设不变 |
| 直线路径 | line | 首点取对象基准位置，点击终点，实时预览；零长度拒绝 |
| 矩形路径 | 新增rectangle交互与几何生成 | 起点为一个角，点击对角点决定宽深，四条直边、闭合返回起点；边长过小拒绝；默认在既有绘制平面的局部XZ轴对齐 |
| 铅笔路径 | freehand | 拖动采样、松开结束，复用简化；少于两个有效点不提交 |
| 钢笔路径 | points | 点击连续落点、预览连线、Enter/双击结束、Backspace退点、Esc取消；本轮沿用已有点选曲线。竞品截图不能证明Bezier手柄，不能声称已经实现完整Bezier编辑 |

角色/道具/组使用既有地面绘制规则，机位沿自身高度平面绘制；世界缩放/旋转下转换为正确文档局部坐标。机位orient保持keep，角色沿线朝向沿用既有规则，不改骨骼步态系统。

### 8.3 矩形的必要技术补充

**不能把四角扔进当前Catmull-Rom后称为矩形。** 推荐在既有Path中增加小范围、向后兼容的可选插值类型（例如`interpolation: 'polyline'`，缺省保持当前centripetal曲线），复用统一弧长/速度/求值接口。polyline按边长分段求值，段内直线插值；闭合边计入长度，转角处朝向行为明确。

这是真正新增能力，允许必要的文档字段扩展，但必须同步schema校验/加载导出/编辑/复制/撤销/PathEditor/overlay与测试；是否提升schema版本按仓库迁移策略决定，不能只加运行时属性导致保存丢失。现有路径缺字段时数学结果保持不变，AI现有ops不因UI新增模式全部扩枚举。

角色矩形默认角点可复用已有stops作为停顿后转向；不保证速度方向在直角处连续，否则会悄悄变圆角。机位矩形遵循当前朝向/注视约束。PathOverlay与导出必须使用同一采样来源，禁止“画的是矩形，播放的是圆角”。

模式清单应区分UI选择项与AI词汇：新增UI的circle/rectangle若是新key，在进入PathTool前统一校验；不要直接重命名现有arc/points/freehand使AI、旧测试或外部调用失效。时间轴、右侧新建路径、其他保留入口使用同一菜单数据/调用流程。
