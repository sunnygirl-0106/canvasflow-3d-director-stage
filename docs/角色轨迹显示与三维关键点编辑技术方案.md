# 角色轨迹显示与三维关键点编辑技术方案

日期：2026-10-23。交付对象：后台 Codex 实施者。基线：`demo` 仓库 `dca9c4c` 加当前工作区未提交修改。本文是待实施方案，不是功能已完成的验收记录。

目标：选中角色自动显示它的运动轨迹；点击轨迹或时间轴节点进入编辑；选中的点可通过 XYZ Gizmo 调整，包括升高和降低；轨迹、角色运动和时间轴同步更新。沿用现有文档、动画求值、渲染和历史架构，以补齐交互为主。

**工程约束：只做必要的局部扩展。需要改动存档格式、替换动画算法、重构整个选择系统或改变已有时间语义时，先向用户提交原因、影响与最小替代方案，等待用户决定。不得以“顺便整理”为由扩大改动范围。**

## 1 已确认的现状

| 能力 | 当前源码与核查结果 | 本次处理 |
| --- | --- | --- |
| 选中角色显示路径 | `PathOverlay.rebuild()` 依据 `app.selectedIds` 显示 `paths`；`selection` 事件触发重建 | 保留，补真实点击及可见像素回归 |
| 点击线显示点 | `PathEditor` 已支持单击选线、双击插点、拖点、删除、退出和撤销 | 扩展，不另写一套路径编辑器 |
| 点的上下移动 | `_beginDrag()` / `_onMove()` 使用固定 Y 的水平面，始终保留原点 Y | 接入 XYZ Gizmo，保留水平直接拖点 |
| 三维路径运动 | `Path`、`PathTrack.apply()` 已按三维位置求值 | 复用，不能把 Y 强制归零 |
| 关键帧运动的轨迹 | `PathOverlay` 只读取 `paths`，不读取 `timeline.tracks` 的 `pos` 轨道 | 为位置关键帧补同样的轨迹显示和点编辑入口 |
| 时间轴定位路径点 | `TrackRows._pathLane()` 已调用 `vertexTime()`、seek 和选点 | 复用，补双向高亮和 Gizmo |
| 时间轴与视口选择保持 | `PathEditor` 在点击任意时间轴区域时清除路径选择；`TimelinePanel` 在面板外点击时清除选键 | 区分键盘焦点与编辑对象，不能无条件互相清除 |
| 拖动实时反馈 | `PathOverlay.setPreview()` 只重画线，不重新求值角色；每次预览全量 rebuild | 复用求值链同步角色，并限定更新范围 |
| Gizmo 提交 | `App` 回调默认提交被选实体的 transform | 增加明确的点编辑分支，防止把点拖动写成角色整体位移 |

上一轮默认坐标、字号和网格修改没有改动上述轨迹交互文件。本次在隔离测试页面运行 `node selftest.mjs pathselect`，现有 16 项检查通过；另核查已有路径显示为一条、位置关键帧轨迹显示为零条，并确认三维路径中间点 Y=2 时角色求值 Y=2。该结果证明基础能力仍在，不能据此断言用户当前场景没有显示问题。

先复现用户症状：记录角色是 `paths` 驱动还是 `pos` 轨道驱动、当前是否导演视角、实体是否可见，以及角色是否为群众成员。记录选中 ID、数据源、overlay 显隐和实际画面；不得清空用户场景或改变机位来掩盖问题。机位视角和截图隐藏辅助线是现有规则，默认空场景没有运动数据也不应凭空显示轨迹。

## 2 必须实现的交互

### 2.1 角色与轨迹选择

1. 在导演视角点击角色本体或左侧角色条目，立即显示其已有运动轨迹。不要求先打开轨迹面板，不要求先点击“显示轨迹”。若保留显示按钮，明确用于暂时隐藏，再次主动选中角色时恢复显示。
2. 只选角色时显示轨迹线；点击线后显示全部可编辑节点，仍只编辑该角色。没有运动数据时不自动创建路径或位置键。
3. 每个节点都可以选中并使用 XYZ 坐标轴，但任一时刻仅为当前节点显示一个 Gizmo。全部节点始终可见，当前节点高亮；不为每个点创建独立 TransformControls。
4. 点击节点或时间轴上对应标记，暂停播放、选中同一个节点、定位到其时刻并显示 Gizmo。视口点选应展开对应时间轴行并滚动到节点；不自动改变导演观察视角或强行弹开用户折叠的整个时间轴。
5. Gizmo 默认使用世界轴平移。拖 Y 轴可升高或降低，拖 X/Z 轴水平移动；不得自动吸附回地面、限制为 Y=0，或把上下拖动解释成时间变化。可保留当前直接拖点的固定高度水平移动方式，并用提示区分两种操作。
6. 点击时间轴中的路径节点或位置关键帧也进入相同编辑流程。多选关键帧继续沿用现有时间轴操作；只有单个位置点被明确选中时显示点 Gizmo，不能任意修改多选集合。
7. 点击空白或“完成”退出点编辑，但只要角色仍选中，其轨迹线继续显示；切换角色清理旧点、旧 Gizmo 和旧预览。重复选择同一角色不能无条件重置正在编辑的点。

### 2.2 拖动与退出

拖动时，节点、轨迹线和角色预览在同一帧使用同一份候选数据。松手后运动按新轨迹播放，保存和重新打开一致。一次拖动最多提交一次历史记录；单击、零位移和取消不产生记录。

Esc 在拖动中取消本次修改并保留节点选择；再按 Esc 退出节点编辑。`pointercancel`、窗口失焦、目标删除、切换文档等中断统一取消预览，恢复控制器状态。用户从播放中开始编辑后保持暂停，不能在取消后自行恢复播放。

删除继续遵守现有输入框保护和焦点规则：路径编辑中 Delete 删选中控制点、Backspace 删整条路径；时间轴聚焦时由时间轴处理键删除。位置关键帧编辑删除的是对应键，不得删除角色。路径至少保留两个点；位置轨道允许剩一个键或变为空，沿用现有校验和显示规则。

## 3 两类节点的数据语义

界面中的“运动节点”包含两类现有数据。统一交互不等于合并存档数据。

| 数据来源 | 空间坐标 | 节点时刻 | 拖动提交 |
| --- | --- | --- | --- |
| 路径控制点 | `paths[].points[index]` | `Path.vertexTime(index)` 派生 | `timeline.updatePath(pathId, { points })` |
| 位置关键帧 | `timeline.tracks[property='pos'].keys[].value` | 键自身的 `t` | `timeline.setKey(trackId, t, value, originalEase)` |

已有 schema 限定同一实体最多一条路径，且路径和 `pos` 轨道不能共存。保留此约束，不复制路径点生成另一套位置键，不保存冗余的节点时刻，不增加第二份动画数据模型。

### 3.1 路径控制点

空间编辑保留 `start`、`duration`、`speed`、`orient`、`interpolation`、`closed`、显式 `stops/stopTimes`。曲线变长或变短后，普通节点到达时刻依据现有弧长和速度规则重新计算；时间轴标记随之移动。总时长不因拖点自动变化，也不能自动改成按默认步速计算。

路径节点是控制点，不能伪装为可任意左右拖动的定时关键帧。本次保留路径已有的时间区间调整、节点定位及停顿操作；若要让每个控制点拥有独立可编辑时刻，需要另行提出时间模型方案并询问用户。不得偷偷给全部节点添加停顿来模拟定时。

闭合路径的“回到起点”标记与首点共享空间点，但定位时刻分别为段末和段首。保留用户点击的是哪次到达这一会话信息，不复制首点进文档。插点、删点沿用 `stopsAfterInsert()` / `stopsAfterDelete()`；索引变化后显式调整或清除选点，不能把 Gizmo 留在另一个节点上。

### 3.2 位置关键帧

空间拖动只改 `value`，保留 `t` 和 `ease`；时间轴横向拖键只改时间，仍使用现有 `dragKeys()`、吸附、复制与覆盖规则。时刻改变后必须更新节点选择引用，不能继续按旧 `t` 提交；同刻覆盖后高亮最终存活的键。

轨迹形状与 `Channel` / `Track` 的实际插值一致。位置键当前是分量线性插值并应用该段 ease，不得为了线条“好看”额外套 Catmull-Rom，导致角色不在线上。单键只显示一个可编辑点，不画伪造的运动线；空轨道不显示点。

旋转、缩放、FOV 和姿态关键帧没有独立的位置轨迹点，不纳入本次三维点编辑。已有 follow 约束覆盖位置时不能展示成可编辑的最终运动轨迹；沿用 `propState()` 的驱动判断，明确显示受跟随控制并禁用被覆盖位置的编辑入口，不自动解除约束。群众成员沿用已有组归属，不创建 schema 禁止的成员独立路径。

## 4 沿用现有模块的实现方案

### 4.1 修改边界

| 现有模块 | 最小必要调整 |
| --- | --- |
| `src/core/PathOverlay.js` | 支持路径及位置键两种来源的线与点；维护当前节点高亮；预览只更新受影响来源 |
| `src/app/PathEditor.js` | 统一视口和时间轴选点入口；管理一次点拖动事务；创建一个可重复绑定的点代理对象 |
| `src/core/TransformGizmo.js` | 复用唯一实例，补充公开的坐标空间设置；保留已有取消、显示和 Orbit 互斥能力 |
| `src/app/App.js` | 在现有 Gizmo 回调中明确区分实体变换与点编辑，集中计算绑定对象及显隐 |
| `src/anim/Timeline.js`、`src/anim/Playback.js` | 为拖动候选数据增加局部、显式的预览参数，仍走原求值顺序 |
| `src/ui/timeline/TrackRows.js`、`TimelinePanel.js`、`keyDrag.js` | 节点双向定位、高亮、时间键移动后重定位；修正无条件清除选择 |
| `src/ui/Inspector.js` | 如增加选中点 XYZ 数值栏，复用同一提交入口；一次输入提交一次历史 |

优先在以上文件中扩展。若 Overlay 与时间轴确实需要共用数据来源解析或采样，可抽取一个小型纯函数模块；只能放两类来源的实际公共逻辑，不能建立插件注册器、通用命令总线、第二个 Store 或新的全局编辑框架。没有重复调用者的薄包装不必抽文件。

`Path`、`PathTrack`、`Track`、`Channel` 继续负责现有数学和运动；`DocumentStore`、`History`、`DocumentController` 继续负责持久化、投影与撤销。不得把渲染对象写入 Store，不需要升级 schema。

### 4.2 选择状态与键盘焦点

轨迹选择继续在现有 `PathOverlay` / `PathEditor` 协作边界内处理。将当前来源和当前节点表达为一种可区分的会话引用，例如路径 `{ kind: 'path', sourceId, index }`，位置键 `{ kind: 'pos', sourceId, keyTime }`。没有选点时仍允许选中一条轨迹。

保持一份可写的当前来源与节点状态。原 `selectedPathId`、`selVertex` 等接口如需兼容调用者，只能从该状态派生读取或委托同一 setter；不得同时维护多份互相同步的可写选择。不要顺带重写实体多选或时间轴 `selKeys`，只对单点编辑建立明确映射。现有 `keyId(trackId,t)` 和 `sameKeyTime()` 继续复用，不新增持久化 key UUID。

视口、时间轴、上一节点和下一节点统一调用同一个选点方法，负责校验引用、必要时选实体、暂停、定位和通知。同一选择重复设置应无操作；来自通知的 UI 高亮不能再调用选实体或 seek，避免事件循环。

移除 `PathEditor` 对任意 `#timeline` 点击的一刀切清空。修改 `TimelinePanel` 的面板外点击规则，让点、轨迹线及其 Gizmo 操作能够保持关联键。键盘焦点仅决定 Delete/Backspace 的归属，不等同于清空空间选择。点击无关实体或明确退出才清理。必须检查捕获阶段监听顺序，不能只在 onclick 中补选中而留下 pointerdown 已误删状态的问题。

### 4.3 一个 Gizmo 和一个点代理

每个点都能获得 XYZ 操作能力，实际复用 `app.gizmo`。点代理是一个普通 `THREE.Object3D`，挂在适当父坐标系中，不能附着于 Overlay 每次重建会移除的顶点球。代理不进入实体列表、存档、角色拾取、截图或导出。

当前绑定对象应只有三种：实体、运动节点代理、无对象。沿用现有 App 显隐入口进行集中判断，避免 `PathEditor._syncSelection()`、`gizmoShouldShow()`、播放事件和截图恢复各自覆盖对方。

点编辑强制 `translate`、`world`；退出后恢复实体原变换模式与空间。`onObjectChange` 和 `onDragState` 根据绑定类型分派：节点分支只能更新节点候选并提交路径或键，不能落入 `App.edited(selectedEntity)` 或自动打键分支。点模式下禁用旋转/缩放，避免工具栏把共享 Gizmo 切成无意义状态。

输入优先级必须明确：Gizmo 轴优先于点，点优先于线，线优先于普通实体选择；绘制模式和正在拖动的操作继续独占输入。当前 `PathEditor._onDown()` 捕获顶点事件，应先排除 Gizmo 命中，不能抢走重叠轴箭头。隐藏时同时禁用拾取。Esc、pointercancel 只能由一次拖动事务处理一次。

### 4.4 坐标转换

路径点和位置键是文档中的父坐标系坐标，不是世界坐标，也不是带模型偏移的 `root.position`。沿用 `docTransformOpts()` 的口径；对于角色，点的 Y 是运动基准高度，模型站立偏移只在动画求值时添加，点代理不能再加一次。

现有顶层路径 Overlay 挂在 `stage.world`，可保持代理与点处于相同局部坐标。Gizmo 使用世界轴时，将变换结果通过对应父对象的世界矩阵转换回文档坐标。要使用完整矩阵处理场景平移、旋转和缩放，不能只除一个 scale。父坐标不是 `stage.world` 时使用实际父对象或明确按组编辑。

绘制用 `LIFT=0.01` 仅防止线与地面闪烁，不得写回路径点或关键帧。所有输入检查有限数；几何退化、射线平行、相机轴向重合时保持最后有效值，不写入 NaN，不在投影不稳定时让点跳远。

## 5 预览与提交事务

### 5.1 一次拖动的生命周期

| 阶段 | 行为 |
| --- | --- |
| 开始 | 校验选点；暂停；保存来源对象引用、Store revision、原点列或原键、时间与 active 状态；固定本次操作目标和 Shift 整体平移意图 |
| 更新 | 从开始快照计算候选值，不累计上帧浮点误差；更新代理与该轨迹；通过原动画求值链预览角色；不写 Store、不写历史 |
| 提交 | 验证 revision 和目标仍有效；有实际变化才调用一次现有 Timeline 写接口；清理预览后按已提交数据重新求值 |
| 取消 | 丢弃候选；恢复代理、Overlay、角色、播放头及编辑前 active/idle 状态；恢复 Orbit 和交互能力；历史与文档不变 |

拖动期间发生其他文档提交时，安全取消当前拖动并给出简短提示，不把旧点列覆盖到新文档。节点被删、键被移动、撤销或导入文档同样处理。不能把 Store batch 跨指针事件长期保持打开。

保留现有 Shift 水平拖点整体平移；若支持 Shift 加 Gizmo，必须用本次轴位移对整条来源的所有点统一平移，且仍一次提交。不要在拖动过程中因 Shift 按键变化切换目标集合。

### 5.2 复用求值链

目前 `setPreview()` 只更新线。为 `Timeline.evaluate()` 增加可选的、非持久化的单一来源替换参数，并在 Playback 的跳转入口透传；实际命名可依现有代码习惯。预览不得替换 `store.document`、临时修改 Timeline getter、调用 `loadDocument()` 或复制整套求值函数。

一次求值内先解析有效的 tracks/paths 集合，再统一用于驱动属性收集、运行时模型与实体求值。其余顺序不变：关键帧 → 路径 → 步态 → 约束。候选只是替换一个已存在来源，不能偷偷增删动画驱动类型。Overlay、时间轴节点标记和角色预览使用同一候选来源，复用 `pathOptionsFor()`。

选点后拖动预览跟随该节点的到达时刻：位置键保持原 `t`；路径点按候选 `Path.vertexTime()` 重新计算，闭合回归点按末时刻定位。播放头和角色必须同步更新，不能只更新 `timeline.time` 而漏掉 `playback.time` 或 tick。取消恢复拖动开始的时刻；提交按最终节点时刻重新定位。

路径连续运动与导出继续使用真实已提交数据。截图、视频导出和文件载入若在拖动中被触发，先通过统一入口取消未提交拖动，再执行原动作；不能让保存或导出的内容混入未提交候选。已有 `withCleanRender()` 的辅助物隐藏逻辑要覆盖点代理 Gizmo。

### 5.3 时间轴与实时性能

几何拖动可能改变路径节点时刻，但不得每次 pointermove 重建整个时间轴或全部场景。按 requestAnimationFrame 合并更新，只更新当前来源的几何、点、节点时间样式和当前角色预览。几何与材质尽量复用，只有节点数量改变时才增删点对象；正常播放只更新亮点与角色，不重建 Path。

复用现有路径模型缓存并按数据引用失效。预览期间一次候选只构建一次模型供同帧使用；如果暂时仍需重建单条曲线，限制在该来源并实测，不能调用现有全量 `rebuild()` 处理每个鼠标事件。不要用明显低精度的预览曲线替代真实曲线，导致松手后人物跳变。

## 6 实施顺序与代码质量门槛

1. 保留当前工作区全部已有修改，记录本任务改动边界。先复现轨迹不可见的具体来源和视角，增加针对真实症状的验收，不先重构。
2. 在现有路径编辑上接入共享 Gizmo、坐标转换和单次提交；确认 Y 轴编辑写入正确点，实体 transform 不被误改。
3. 增加局部候选预览，使路径和角色同帧变化；验证取消、撤销、重新加载与导出。
4. 接通时间轴双向选择，保留键拖时间、路径节点派生时间以及所有现有快捷键语义。
5. 补齐普通 `pos` 关键帧轨迹，沿用上面同一套选择、Gizmo、事务和绘制能力；不复制第二套编辑器。
6. 只清理本次产生的死分支、重复监听及被替代代码；运行下节验收并交付证据。

### 7.2 测试分工

纯函数及求值测试覆盖坐标往返、非平面路径、位置插值一致、选点索引变化、时间与 ease 保留、事务取消和版本冲突。优先扩展现有 `pathPicking`、`pathTiming`、`timeline`、`store/history` 测试；只在现有文件不合适时新增紧凑测试模块，不为常量或一行包装编写镜像测试。

真实浏览器测试扩展 `pathselect`、`path` 和 `tl`：从用户点击到鼠标拖轴再到播放结果完整覆盖。旧“点击任意时间轴即清空轨迹选择”的断言应替换为本方案的焦点与选择规则；其他断言不能为了通过而放宽。对未提交预览逐帧记录 Store revision 与历史数量，确认稳定。

执行 `npm run check`、`npm run build` 和相关浏览器套件；涉及共享 Gizmo/Playback 的变动须回归 `default`、`pathselect`、`path`、`tl`、`cam`、`export`。根据实际改动选择现有用例，不反复跑与改动无关的大套件来代替定位。

性能验收在固定窗口和同一设备记录一条 100 节点曲线拖动约 5 秒的帧耗时分布、长帧、Store 提交次数及 WebGL 资源变化，并与修改前比较。正常播放无逐帧几何重建，反复进入退出编辑无持续资源增长；明显退化需定位修复后交付。

交付包含：改动文件及理由、用户不可见轨迹的具体根因或尚未复现的边界、测试结果、带 Y 轴拖动及时间轴联动的截图或短录屏、一次撤销/重做与重载验证、性能记录。全部满足后才能写“已完成”；只显示坐标轴、只移动点但角色不更新，均不算完成。

## 8 需要先询问用户的变更

出现以下需要时停止相应扩展，继续完成不依赖它的已授权工作，并向用户说明原因、受影响模块与较小替代方案：

- 为每个路径控制点新增独立时间、修改停顿语义、改变匀速规则或迁移存档格式。
- 引入另一套动画引擎、状态仓库、Gizmo 库，或对整个 App/时间轴进行框架级重写。
- 改变群众成员归属、自动移除 follow 约束，或把角色运动升级为跳跃、爬坡、碰撞和地形适配系统。
- 为了实现轨迹编辑，必须改变用户现有场景数据、机位构图或已确认的默认参数。

以上均不属于本次默认授权。普通局部接口扩展、复用现有组件、补充测试和修复事件冲突按本方案直接实施，无需反复请求确认。
