3D 导演台 · 阶段 B 起

导演台技术规划

阶段 A（换人偶、骨骼档案、默认站立）已经在做。这一页记录从阶段 B 开始的路线：先立规矩，再长功能；每一节先讲"做什么"，再讲"为什么"，关键概念配一个能动手玩的小演示。

三条铁律

① 场景即数据界面上能看到的每一个状态，场景文档里都有对应字段；反过来也成立。人改它，AI 写它。
② 状态 = f(t)任意时刻的画面由 evaluate(t) 算出来，不靠上一帧累加。播放头随便拖，导出随便跳帧。
③ 预设都有稳定英文名stand / walk / run / half_orbit / circle——这是 AI 的词汇表，起了就不改。

阶段 B · 1–2 天

场景文档：把导演台变成一份 JSON

做什么。定义一份 schema：角色（体型、颜色、名字、位置旋转缩放、姿势预设名）、编组、道具、机位（变换、FOV、注视目标、跟随目标）、路径（类型、顶点、时长、是否沿路径朝向）、时间轴（时长、帧率、各轨道关键帧）、场景（天空、地面、全景）。配一个校验器，不合法的文档拒绝加载并说明哪里错。现有的撤销重做接到这份文档上。

为什么排在最前面因为后面每一个阶段的输出端都是它：手动操作是人改文档，AI 生成是模型写文档，识图导入是视觉模型写文档里"位置"那部分，保存、撤销、导出都是它的序列化。竞品"一句话生成场景"之所以能做，前提就是整个场景能被一份文本完整描述。没有 B，H 做不了；B 做歪了，后面全歪。

校验器为什么重要：竞品生成时失败过两次才成功，大概率就是模型写出来的文档没过校验。宁可拒绝，也不要加载半个场景。

左边是场景文档，右边是它渲染出来的俯视图。改左边的数字，右边立刻变；写一个词汇表里没有的姿势名，校验器会拦下来。

阶段 C · 2 天

动画内核：没有界面，只有"给我时间 t，还你场景状态"

做什么。五个小模块：Channel（哪些属性能动画：角色的位置/旋转/缩放，机位的位置/旋转/FOV）、Track（一条属性上的关键帧 + 插值）、PathTrack（路径型轨道）、Constraint（跟随、注视、沿路径朝向）、Timeline.evaluate(t) 把它们按固定顺序算一遍。再加一个播放时钟和程序化步行 Locomotion。这一阶段不做任何界面，用脚本验证。

为什么先做内核、后做面板面板只是内核的遥控器。先做面板，逻辑会散落在各个按钮的点击事件里，后面"拖播放头和手动改值打架"、"路径改了关键帧不跟着变"这类 bug 很难修。先把内核做成一个纯函数，面板怎么做都不会错。

概念 1 · 关键帧与补间

你亲手定的几个时刻的值叫关键帧；两帧之间引擎自动算出来的每一帧叫补间（Tweening）；算的方法叫插值，最简单是匀速（线性），也可以先慢后快（缓动）。Rive、After Effects、Blender 的时间轴都是这同一个模型。

演示 · 拖播放头，看补间
三个菱形是关键帧，小球的位置由 evaluate(t) 算出来。换插值方式，关键帧不变，中间的路变了。

概念 2 · 旋转不能直接线性插值

从 350° 转到 10°，按数字线性插值会绕一大圈转 340°；人眼看它只需要转 20°。3D 里用四元数做旋转插值，天然走最短路。你不用懂它的数学，记住一条：位置用线性，旋转用四元数，three.js 都自带。

演示 · 两种旋转插值

概念 3 · evaluate(t) 的固定顺序：关键帧 → 路径 → 约束

顺序定死，就不会"运镜和跟随打架"：跟随是约束，永远在最后一步覆盖机位位置，所以开了跟随，机位自己的关键帧自然失效。另一条规则：没打关键帧的属性保持手动值，这就是"手动改了数值，播放时会被关键帧覆盖（除非打成关键帧）"的来源，也让现有的 gizmo 拖动不用改。

演示 · 开关"跟随"，看第三步如何覆盖前两步
① 关键帧轨道② 路径轨道③ 约束

概念 4 · 程序化步行：相位由路程驱动

角色沿路径移动时，用关节滑条按公式生成走路：左腿抬腿 = A·sin(相位)，右腿取反，手臂和对侧腿同相。关键是相位 = 已走路程 ÷ 步幅，而不是由时间驱动。这样走得快步子就快，脚不会在地上打滑。速度超过阈值自动切跑步（步幅更大、膝盖更弯、身体前倾）。速度为 0 时不介入，角色保持手动摆的姿势。

阶段 D · 2–3 天

时间轴面板：给内核装遥控器

做什么。你清单的第一、二条：底部工具坞入口、播放/暂停/循环、时间显示与总时长、帧率下拉、可缩放刻度尺、可拖播放头、轨道列表与子行、关键帧增删拖、属性面板旁的实心/空心菱形、播放头移动时数值实时跟随。

为什么它是"薄"的面板里每个控件都只做一件事：读内核的状态显示出来，或者把一个用户动作翻译成对内核的一次调用。打关键帧 = 往 Track 里插一条；拖播放头 = 调一次 evaluate(t)；改帧率 = 只改吸附和导出，内部时间一直是秒，已有关键帧不会挪位。面板不持有任何自己的状态，所以它坏了也只是显示错，不会把数据弄脏。

实心/空心菱形的判定也是查内核：当前时刻这条 Track 上有没有一个关键帧的时间等于 t。

阶段 E · 2–3 天

角色路径：路径是源头，不是一堆关键帧

做什么。角色面板第三页签"运动轨迹"：时长、路径自身的变换、"沿路径朝向"开关；五种绘制（圆环、直线、矩形模板一键生成；铅笔在地面拖；钢笔点锚点）；路径显示为蓝线、顶点可拖、整条可用 gizmo 移动；开启沿路径朝向后锁定角色 Y 旋转。

为什么不把路径烘成关键帧竞品说"轨迹生成后自动翻译成关键帧"。如果真烘成几百个位置关键帧，用户再拖一下顶点，关键帧就和路径脱节了。我们把路径做成独立的轨道类型 PathTrack：时间轴上只显示起点和终点两颗菱形（代表路径的时长），位置每帧从曲线实时算。用户看到的效果一样，但路径随时可改，文档里也只存几个顶点而不是几百个关键帧。

曲线用 Catmull-Rom 样条：经过每一个锚点、自然平滑，three.js 自带 CatmullRomCurve3。朝向就是曲线在该点的切线方向。

演示 · 点几下画路径，拖进度看位置和朝向
在画布上点击加锚点（钢笔），或用模板一键生成。蓝线是样条，角色位置 = 曲线在 u 处的点，朝向 = 切线。
阶段 F · 2–3 天

机位：运镜是路径，注视和跟随是约束

做什么。你清单的四、五、六条：7 种运镜预设（环绕、半弧、推近、拉远、升降、横移、螺旋上升），分"替换"和"追加"两组，追加可多段拼接；机位也能用五种方式绘制轨迹（紫线，可离地）；注视目标（坐标或某个角色/组）；FOV 关键帧（变焦）；跟随目标（每帧约束：机位 = 角色位置 + 偏移，始终看向角色）；播放时视口切到主机位画面并隐藏辅助线，整段视频只有一个主机位。

为什么运镜预设只是"路径生成器""环绕"本质上就是一条围着目标的圆形路径加一个注视约束；"推近"是一条指向目标的直线。所以 7 种预设不需要 7 套代码，它们都是"按参数生成一条 PathTrack + 设一个注视目标"。追加拼接 = 把两条路径首尾相接。这也是阶段 E 的路径系统直接复用的地方。

跟随和运镜互斥的原因在阶段 C 已经定了：跟随是约束，排在最后，开了它运镜就被覆盖。

演示 · 7 种运镜（俯视）
绿点是被拍的角色，紫线是运镜路径，紫色三角是机位，细线指向它正在看的点。升降和螺旋的高度用数字标出。
阶段 G · 1–2 天

导出视频：离线逐帧，不是录屏

做什么。名牌从 DOM 覆盖层改成 3D 精灵（否则进不了画面）；用 WebCodecs 逐帧渲染：第 i 帧 = evaluate(i / fps)，渲染、编码、封装成 MP4；Chrome/Edge 可用。产出一个 MP4 文件，"生成画布节点"的对接取决于 CanvasFlow 主产品架构，另议。

为什么这一步依赖铁律 ②录屏（MediaRecorder）是实时的：电脑卡一下就掉帧，出来的还是 WebM。离线逐帧是"我要第 i 帧，你算给我"，机器慢只是导出久一点，帧数一帧不少。这要求任意 t 的画面都能独立算出来，也就是 evaluate(t) 不能依赖上一帧——阶段 C 就是为这一刻准备的。

阶段 H · 2–3 天

AI 生成：模型不点按钮，它写文档

做什么。文本生成：提示词 = 场景文档 schema + 预设词汇表 + 几个范例 → 模型输出一份文档 → 校验 → 不过则把错误信息喂回去重试 → 通过则加载。对话式修改：模型输出对现有文档的补丁，不重写全文。识图导入：视觉模型只负责写"角色数量、位置、朝向、机位方向"，用户选插入或覆盖。

为什么它反而是最薄的一层到这一步，难的事都做完了：文档格式定了（B），预设有名字了（③），路径和运镜能用几个参数描述（E、F）。AI 要做的只是"用这套词汇写一份合法文档"。它写错了，校验器会告诉它哪里错；它写对了，引擎就能放出来。竞品输入"三个人玩老鹰捉小鸡"得到的那个场景，就是这样一份文档。

阶段 I · 穿插

内容补齐

姿势预设从 14 个补到竞品的 24 个（坐姿、蹲下、单膝跪、双膝跪、倚靠、看手机等）；儿童、胖、壮等体型从 BodyKun 派生。这些是数据，不是代码：阶段 A 之后加一个预设就是在 posePresets.js 里加一行，加一个体型就是在档案表里加一项。

另外两条独立的线：虚拟相机（手机扫码手持录运镜）本质是"从外部喂一串机位关键帧"，接口在阶段 C 就有了；"生成画布节点"取决于 CanvasFlow 主产品的架构。

总量约 15–20 个工作日。A 与 B 并行；C 必须在 D 之前；H 只依赖 B 和 C。每个阶段结束都有一个能看到的东西。
