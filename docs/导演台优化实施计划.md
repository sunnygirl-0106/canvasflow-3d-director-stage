# 导演台优化实施计划：默认场景、机位播放与时间轴对齐

日期：2026-10-21。代码阅读基线：`2d39792`。本文件是交给后续 Codex 的实施规格，本轮只制定计划，不修改产品代码。

## 1. 目标与证据边界

用户明确要求：首次进入即有一个机位、一个人偶；默认 10 秒；时间轴细节与竞品对齐，包含帧率和帧操作；初始相机与主体的空间关系需要校准；点击播放应观看机位所拍画面，而不是站在第三视角看相机沿轨迹移动。代码质量优先，禁止为视觉模仿重复建设基础系统。

参考图已保存到仓库：[竞品截图 01](references/director-competitor-01.png)。后续实施不依赖聊天临时附件。

证据必须区分：

- **截图确定**：左侧一个“机位1”、一个“角色A”；顶部导演视角/机位视角；时间显示 `9.97`、总时长 `10.00 s`；右侧 `30 帧/秒`；秒标尺；青色实体条与位置子轨道、菱形节点；主机位行；绘制轨迹入口；缩放滑条；底部横向滚动条；右侧导出入口。
- **用户确定的产品行为**：默认一机位一人偶、点击播放自动进入摄影机画面。这不是由静态截图推导出来的竞品交互。
- **截图无法确定**：竞品初始相机位置、FOV、相机到主体的精确距离、播放暂停后的行为、短刻度是否逐帧、截图是否为初始场景。该图已有运动轨迹且时间接近末尾，不能把此时的角色坐标直接当作初始化参数。
- 图中只显示一个角色。用户提到“两个人偶”的距离问题，本轮以其明确的新默认“一机位一人偶”为准；另外用双人测试场景验证取景，不把第二个人偶加回默认场景。

## 3. P0：首次可操作画面为“一机位一人偶”

### 3.1 默认场景契约

1. 新鲜启动只含“角色A”与“机位1”；默认站姿，角色双脚贴地，无预设动画、路径或约束。
2. `timeline.duration=10`、`timeline.fps=30`；`scene.activeCameraId` 与 `timeline.mainCameraId` 都指向机位1；播放头为0，未播放。
3. 默认导演视角，便于摆放；初始选中角色A，右侧显示角色属性。时间轴展开，角色与主机位均可见。
4. 机位朝向角色身体中心，立即切到机位视角能得到完整可用的全身构图。不要继承用户此前偶然拖动的导演视角来生成默认机位。
5. 初始化期间允许加载提示；首个可操作场景必须是完整的一机位一人偶，不能先让用户操作空场景或半成品。角色加载失败需明确错误与可重试入口，不能把失败状态当ready。
6. 初始化完成后再建立撤销起点、开放交互和显示恢复提示。保留当前“提示恢复旧存档”的策略，不强制自动恢复。
7. 导入、恢复、AI清空场景不应用seed规则；用户旧场景即使无人或无机位，也不得被偷偷补对象、重置时长或重摆位置。

### 3.2 最小实现范围

- 在 `main.js` 或一个职责单一的小初始化模块中装配默认场景，复用文档生成/加载和现有实体构造能力。优先用现有原子加载路径处理资源准备与失败，避免逐项公开半成品。
- `createEmptyDocument()` 继续表示真正的空场景，不能把种子对象塞进这个通用工厂。
- 默认实体数据进Store，选中/加载中等会话状态留在应用层；不要直接修改Three对象后忘记提交文档。
- 利用现有加载完成/历史状态定义ready；确实需要新增ready状态时只保留一个来源，供UI和测试共用。
- 检查初始化事务不触发覆盖旧自动存档；`AutoSave` 目前忽略history reset，应维持这一约束。

### 3.3 初始构图校准

必须分开校准两个相机：导演观察相机与场景中的拍摄机位。不能为了让导演画面变远而把实际拍摄机位也无差别移远。

建议先使用现有 `front_mid` 作为机位参数起点（按主体身高2.2倍距离、40° FOV生成），不是最终对齐结论。默认角色文档位置先定为原点、朝+Z；使用现有模型包围盒/骨骼测量取得主体中心与身高，不硬编码模型root的Y偏移。

导演相机采用独立的初始观察构图，保留大面积舞台和操作空间。以截图中央视口为比较区域，人物高度约为视口高度20%～25%，脚底约在视口高度80%～84%，水平位置靠中。以上是截图估读的校准起点，不是竞品坐标；轨迹线和当前坐标不复制进默认场景。

实施需输出：角色位置、拍摄机位位置/朝向/FOV、导演相机位置/target，以及导演/机位两个视角截图。拍摄画面的暂定验收为完整全身、无裁头裁脚、主体高度约占有效画面60%～75%，此比例属于本计划建议而非截图事实。若获得竞品原始初始化参数，再替换为准确值。

不要全局修改 `frameAll()` 的既有自动取景意义；只调整默认入口，并使“重置视角”返回新的默认导演构图。显式“对准主体”及已有背景取景行为应保留。

## 4. P0：播放即观看机位画面

### 4.1 行为规格

| 操作/状态 | 期望行为 |
| --- | --- |
| 导演视角点击播放或Space | 先解析有效机位并切到机位画面，再开始推进时间；第一帧不能短暂显示第三视角 |
| 机位视角点击播放 | 按主机位规则播放，界面明确显示当前出画机位名 |
| 暂停 | 保持机位画面和当前时间，支持逐帧检查 |
| 非循环播完 | 保持机位画面，停在时间轴末端；再次播放从0开始 |
| 循环播放 | 时间循环，机位视角不闪回导演视角 |
| 停止/Esc | 保留现有“回0并恢复手动值”的含义，结束预览，回到开始播放前的编辑视角；不要混同“暂停” |
| 用户点击导演视角标签 | 先暂停并退出成片预览，再允许编辑轨迹；拖播放头可在导演视角检查空间变化，不强制切回 |
| 无有效机位 | 不启动播放，明确提示添加/选择机位；不悄悄播放第三视角，也不自动新建机位 |
| 主机位删除/导入替换 | 预览中先安全暂停、释放旧相机与辅助元素状态；按统一规则解析存活机位，若无则回导演视角 |
| 导出/取消/失败 | 恢复导出前约定的预览状态；不误退出或重复进入洁净渲染，不破坏播放头 |

无主机位但有相机：回退到当前机位→选中机位→第一个有效机位，并显示实际出画名。回退本身不要偷偷写入mainCameraId或制造撤销记录。多机位只按这条规则，不因选择了角色或其他对象改变正在看的主机位。

### 4.2 实现原则与风险

- `Playback` 继续只负责时间推进；不在 `anim/Playback.js` 导入App/UI或操纵DOM。
- 在应用层统一处理开始/结束预览。播放按钮和Space复用入口；检查所有直接 `play()` 调用，使产品入口遵守同一语义。不能仅修按钮而漏掉快捷键。
- 如使用播放状态事件协调，检查其发出顺序：当前 `play()` 先 `_apply()` 再发state，首次渲染前必须完成视角切换。也不能把任意 `timeline.active`（包含seek与导出）都误当成用户开始播放。
- 检查 `setCameraView(true)` 当前会选择机位并通过Store写activeCameraId。自动预览不能只为临时看画面而生成文档修改/撤销记录或丢掉原选中对象；必要时小范围拆分“用户选择机位”与“应用渲染机位”。
- 复用 `exportCamera()` 的解析规则；若命名不适合共享，可迁为一个应用层纯解析帮助函数，原调用一并调整。禁止复制第二份优先级判断。
- 预览隐藏路径、控制点、gizmo、选中环、机位模型/视锥等编辑辅助物；网格与名牌策略与现有导出画面一致，不擅自删场景地面/背景。
- 复用洁净渲染生命周期并与导出嵌套配对；所有退出路径含异常都恢复。避免每次tick调用begin导致计数泄漏。暂停仍需维持预览洁净状态。
- 保持 `timeline.evaluate(t)` 为唯一动画求值来源；相机位置、朝向、FOV、lookAt/follow都从同一时刻求值。不要另建录像播放器、额外RAF循环或逐帧写Store。
- 预览与导出采用相同机位、时间和有效取景区域；屏幕自适应显示可留边，但不能因viewport比例改变成片构图。复用现有frame/导出尺寸机制，补宽屏与竖屏验证。

## 5. P1：时间轴按参考图对齐

此阶段属于本轮完整交付，不是可跳过的美化；P0先合并以降低定位风险。

### 5.1 布局与视觉

截图比例参考：时间轴上缘约在整页74%高度；左侧轨道信息列约占整页18.4%；标尺从该列右边开始。数值来自归一化截图估读，不能直接把3840像素图片尺寸当作CSS尺寸。

| 区域 | 对齐要求 | 落点 |
| --- | --- | --- |
| 第一行 | 左侧播放/时间/循环/移除轨道，中间秒标尺，右侧缩放、折叠、30帧/秒、导出 | `Transport.js`、`TimelinePanel.js`、CSS |
| 时间显示 | 当前 `0.00` + 总时长 `10.00` + `s`，替换mm:ss.cc的主显示；总时长可编辑 | `Transport.js` |
| 初始可见范围 | 参考图可见0～约5秒，完整10秒可横向滚动；初始不再强制fit全部10秒；保留显式适配全长 | `TimelinePanel.js` |
| 标尺 | 默认每1秒标签，短刻度分层、缩放后逐帧可辨；不把0.1s短刻度伪称为1帧 | `Ruler.js` |
| 缩放 | 显式滑条复用现有pps和锚点换算；按钮/滑条/滚轮状态一致 | `TimelinePanel.js` |
| 角色主行 | 角色名、折叠箭头、“绘制轨迹”、青色时间条；对应位置子行有缩进和菱形节点 | `TrackRows.js`、CSS |
| 位置子行 | 上/下关键帧定位、当前属性值、关键帧状态入口；优先复用animState的打键规则 | `TrackRows.js`、`animState.js` |
| 主机位行 | 对应真实mainCameraId，显示主机位语义与绘制轨迹入口；其他机位仍能辨认，不把所有相机都叫主机位 | `TrackRows.js` |
| 颜色 | 中性深灰底、青色选中/轨迹/关键帧，减少目前红色播放头、绿色路径、紫色约束的杂色 | `timeline.css` |
| 滚动与冻结 | 名列不随横向滚动，标尺/播放头/节点共用坐标原点；底部横向滚动条可操作 | `layout.js`、面板/CSS |
| 展开策略 | 新用户常见桌面高度默认展开；尊重用户主动保存的折叠偏好 | `TimelinePanel.js` |

轨道条语义必须明确：实体主行的全长条仅表示场景内持续存在/可编辑范围，由duration派生；它不是新建的动画片段，不给未动画对象生成假关键帧。真实路径区间仍来自path.start/duration；位置轨道菱形必须来自真实关键帧，禁止把路径控制点伪装成位置关键帧。已存在的旋转/缩放/FOV/约束可在展开后显示，不能为模仿截图删除能力。

“绘制轨迹”调用现有PathTool；“移除轨道”有明确作用对象，仅删除选中动画轨道/路径，不删除角色或机位。空选择时禁用。一次批量移除只记一步撤销，检查现有 `removeAllAnimation()` 多次提交问题，并在应用事务边界合并。

现有自动打键、吸附、主机位选择、帧步进和停止功能保留；截图首行放不下时移到明确的更多菜单/设置，不让 `overflow:hidden` 静默截掉关键操作。时间轴导出入口复用同一个ExportModal；demo没有真实画布回传契约时写“导出视频”，不得假装已实现“导出视频到画布”。

截图中部分小图标语义无法可靠辨认，不凭外形发明功能。以清晰tooltip和已有动作实现最接近的布局。

### 5.2 帧率、帧数与末端约定

- 10s × 30fps = **300个视频采样帧**；零基索引0～299，采样时刻0～299/30=9.966666…s，显示为9.97。
- `10.00s` 是时间轴区间终点，允许跳转/放置终点关键帧；它不是导出第301帧。静态截图显示9.97不能证明竞品播放停止规则，本轮保留现有播放到duration的语义。
- 秒存储保持不变，不迁移成整数帧schema。UI步进与吸附按 `round(t*fps)/fps` 统一计算；显示两位小数不作为内部时间精度。
- 30fps连续前进30帧应到1s，后退30帧回0；跳帧、拖键、移动区间、缩放/滚动后吸附一致。边界夹取与duration非整帧的情况必须覆盖。
- fps使用已有timeline值；切换24/25/30/60不改变已有动画秒数或总时长。导入非常规合法fps仍可显示，不强制改成30。
- 实时播放可以按墙钟连续求值，不能因“30帧/秒”改成每次RAF固定加1/30造成不同设备播放速度不同。fps用于时间编辑及离线导出采样。
- `frameCount()` 和 `renderFrames()` 已有不含终点的采样规则，优先保留并测试；不得因9.97展示需求把duration改成9.97。

## 6. 质量红线

1. 不加新框架、时间轴库、全局事件总线、第二份Store或新播放器；当前Vite + three.js + 原生模块足够。
2. 遵守现有依赖方向与import检查。文档/动画底层不得反向依赖UI/App。
3. 既有文档结构足够表达本轮需求，不新增schema版本；选中、预览生命周期、缩放等会话状态不塞进文档实体。
4. 单一真相来源：时长/fps读timeline、机位解析共享、几何坐标走既有换算、所有持久化修改走Store事务。
5. 不在每个tick重建轨道DOM/导出整份文档/捕获撤销快照；播放仅更新必要的时间、播放头和属性显示。保留按需渲染与重建合并。
6. 新增模块必须有独立职责和实际复用价值；禁止空壳manager、重复包装与为截图硬塞大量绝对定位。样式限于导演台/时间轴作用域。
7. 不写吞异常的catch、关闭lint、删断言、放宽关键容差来“让测试通过”。新行为替换旧断言时保留其有效业务覆盖。
8. 不改变本轮无关的AI、骨骼、步态、资产、路径插值与运镜数学。读到的邻近问题另列，不顺手重构全仓库。
9. 测试优先覆盖用户可观察行为、数据不污染、资源清理与边界；不添加仅断言函数调用次数或镜像实现的低价值测试。
10. 清理本轮废弃分支、未使用样式和监听器；有可反复进入退出的订阅/辅助渲染状态必须可释放。

## 7. 实施批次与验收

### 批次A：默认场景及测试夹具

### 批次B：播放预览

### 批次C：时间轴与帧体验

复用既有组件调整首行布局、宽度/高度、青色视觉、轨道信息、缩放和导出入口，补帧数边界。不得只改CSS而漏交互。

验收：10s/30fps导出恰好300帧，最后采样9.966666…；时间显示9.97不改变内部精度；前后帧步进正确；缩放与横滚后点击标尺/拖键无偏移，0s/10s节点可选；初始0～约5s可见且可滚到10s；关键入口在常见桌面宽度不被裁掉；删除轨道和撤销结果正确。
