# 技术规划｜机位视角（POV）下开放全部编辑操作

> 目标读者：Claude Code（据此实现）
> 关联背景：3D 导演台 — 左侧场景列表机位交互调整 & 机位视角编辑能力对齐

## 目标

使机位视角（POV）与导演视角的编辑能力对齐：POV 下可选中角色/道具，使用画布三色 gizmo 进行平移/旋转（含沿镜头进深方向），并保留右侧「属性 / 姿势」参数编辑。对齐竞品"透过镜头直接调"的体验。

## 现状与根因（为何不能只改显隐判断）

1. `main.js` 中 `TransformGizmo` 用 `stage.camera`（导演相机）构造，其内部 `TransformControls` 始终以该相机计算手柄投影与拾取。POV 渲染用的是 `stage.activeCamera`，两者不一致 → 手柄错位、无法拖动。
2. `src/core/Selection.js` 的 `_pick()` 用固定的 `this.camera`（导演相机）做 `setFromCamera` → POV 下点击画布选不中正确物体。
3. `TransformGizmo` 的 `dragging-changed` 回调在拖拽结束时执行 `orbit.enabled = true`，会把 POV 下本应锁死的环绕重新打开。
4. 多处主动在 `cameraView` 下隐藏 gizmo / 选中环：`App._reflectPrimary()`、`App._endCleanRender()`，需改为按"是否应显示 gizmo"的统一判定，而非一刀切按视角隐藏。

## 阶段一：核心打通（让 gizmo 在 POV 下可用）

1. **`src/core/TransformGizmo.js`**：新增方法 `setCamera(cam)`，内部执行 `this.control.camera = cam;`（切换手柄投影/拾取所用相机）。
2. **`src/app/App.js`**：抽出"同步编辑相机"逻辑，在**渲染相机发生变化的所有入口**调用：`setCameraView(on)`（进/出 POV）、`setActiveCamera(id)`（切换出画机位）。同步内容：
   - `this.gizmo.setCamera(this.getRenderCamera())`
   - 让 `Selection` 使用同一相机（见第 3 点）。
3. **`src/core/Selection.js`**：将 `_pick()` 中的 `this.camera` 改为动态获取当前渲染相机。实现方式二选一：构造时注入 `getCamera()` 回调并在 `_pick` 中调用；或保留 `this.camera` 但由 `App` 在渲染相机变化时更新 `selection.camera`。确保 POV 下点击画布能正确命中角色/道具。
4. **OrbitControls 守卫（关键，避免引入新 bug）**：修改 `TransformGizmo` 的 `dragging-changed` 处理，使"拖拽结束恢复环绕"服从视角状态——POV 下不得重新启用环绕。建议：构造时接收一个 `orbitAllowed()` 回调（返回 `!app.cameraView`），处理逻辑改为 `orbit.enabled = !e.value && orbitAllowed()`。
5. **放开 gizmo 显隐判定**：在 `App` 中新增判定 `_gizmoShouldShow()`：`选中实体存在 && 不满足(处于 POV 且 选中实体就是当前出画机位 activeCameraId)`。即 POV 下对角色/道具显示 gizmo，但**不对"正在透过它看"的出画机位显示 gizmo**（无意义且遮挡）。
   - `_reflectPrimary()`：将 `this.gizmo.setVisible(!this.cameraView)` 改为 `this.gizmo.setVisible(this._gizmoShouldShow())`。
   - `_endCleanRender()`：将 `if (this.selected && !this.cameraView) this.gizmo.setVisible(true)` 改为按 `_gizmoShouldShow()` 恢复。

## 阶段二：细节与正确性

6. **截图/预览保持洁净**：`_beginCleanRender()` 仍需隐藏 gizmo、选中环、相机可视化（现有逻辑保留）；仅确认 `_endCleanRender()` 按新判定恢复，避免导出的机位截图里出现 gizmo。（截图路径由 `src/app/ShotManager.js` 的 `beforeRender/afterRender` 调用这两个钩子。）
7. **选中环策略（已定：显示，但截图不进构图）**：POV 下正常显示脚下蓝色选中环作为选中反馈；截图/预览时由现有洁净钩子隐藏，不进构图。具体改动：
   - `App._reflectPrimary()`：把 `this.selection.highlight(this.cameraView ? null : ent)` 改为 `this.selection.highlight(ent)`，使 POV 下也创建并跟随选中环。
   - `App._endCleanRender()`：把 `this.selection.ring.visible = !!this.selected && !this.cameraView` 中的 `&& !this.cameraView` 去掉，改为 `this.selection.ring.visible = !!this.selected`。
   - **无需改动** `_beginCleanRender()`：它已将 `ring.visible = false`，截图/预览自动不含选中环。
8. **保持不变项**：POV 下点击左侧机位仍为"切换出画机位"（不弹 gizmo）；相机不支持 scale 的限制保留；姿势编辑经右侧「姿势」滑条已可在 POV 生效，无需改动（本产品无画布骨骼直拖）。

## 阶段三：验证（回归清单）

- 运行 `selftest.mjs`，确认无回归。
- 手动验证矩阵：
  - POV 下选中角色 → 平移/旋转手柄出现且与所见画面对齐；可沿三轴拖动（含镜头进深方向）。
  - 拖拽结束后 POV 仍锁死（不会被重新允许环绕）。
  - POV 下切换出画机位 → gizmo 重新对齐到新相机投影。
  - POV 下点击画布空白/角色 → 选择行为正确。
  - POV 下选中角色可见选中环并跟随移动。
  - 机位截图/预览导出画面中**无 gizmo、无选中环**。
  - 导演视角全部编辑行为不受影响。

## 前置说明

本规划假设上一轮"导演视角下点左侧机位＝仅选中、不自动进 POV"的改动已合入；两者相互独立，但建议一并测试交互闭环。
