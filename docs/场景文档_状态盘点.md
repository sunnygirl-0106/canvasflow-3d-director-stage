## 0. 盘点中发现的、与任务书前提不符的三件事（需要你先拍板）

1. **现在没有撤销重做。** `HistoryModal` 是「画布历史资产」选择弹层（图片/视频历史 → 选一张 2:1 图作全景），
   与撤销重做无关；全工程没有 undo/redo、也没有 ⌘Z 快捷键。所以第 4 步不是"改后端"，而是"从零新建"，
   并且**没有现成的撤销 UI 可复用**。详见 §6。
2. **id 会撞。** `Entity` 用模块级 `_idSeq` 生成 `e1, e2…`。会话内单调递增、不会复用，
   但**导入文档后就会撞**：新页面 `_idSeq=0`，导入含 `e3` 的文档，再添加实体就会生成 `e1/e2/e3`。必须改随机短 id。
3. **Character 不知道自己的 body key。** 它只存了 `spec = {url, profile, height, girth}`，没有 `'male'` 这种键；
   复制角色也是拷 spec。需要给 Character 加 `this.body`（复制 / 群众成员一并带上）。

## 4. 截图（ShotManager）—— 建议 **C，不进文档**

截图是产出而不是场景：Blob 很大、是渲染结果、可以随时由场景重拍。但有两个必须处理的耦合：

- 截图挂在 `cameraId` 上。撤销 / 导入走"清空再重建"，如果清空时复用 `app.remove()`，会触发
  `shots.removeForCamera()`，**一次撤销就把截图全删了**。→ `loadDocument` 的清空走专用路径，不碰 ShotManager；
  重建后同 id 的机位自然接回原截图。
- 导入一个别人的场景后，残留截图的 cameraId 可能找不到机位 → 导入（不是撤销）时清掉孤儿截图。

`_seq / _count / selectedShotIds` 同为 C。

## 5. 全景图 —— 同意用 `assets` 表

```
assets: { "a8k2…": { type: 'image', name: '晴日蓝天 · 2:1', dataURL: 'data:image/jpeg;base64,…' } }
scene.panorama: { assetId: 'a8k2…', rotation: 0, radius: 60 }
```
- 本地上传：读成 dataURL 存入 assets。
- 从「历史记录」选的内置全景（同源 `./assets/panoramas/*.jpg`）：建议**存 `url` 而不是 dataURL**
  （`{type:'image', name, url}`，二者择一），否则每张 0.5–1MB 塞进每一份撤销快照和 localStorage（上限约 5MB，会爆）。
  这也正好是"以后换外部存储"的形态。
- 实体只引用 assetId；校验 assetId 必须存在。`name` 用于面板上显示的「已连接全景图」标题。
- 没有全景时 `scene.panorama = null`；这时面板上置灰的旋转/半径滑条值会回到默认（0 / 60），可接受。
- 撤销快照栈：assets 字符串不变时快照去重仍然有效，但每份快照都会带着 dataURL —— 见 §6 的内存处理。

## 6. 撤销重做 —— 现状与方案

**现状：没有。**（`HistoryModal` 是资产历史弹层，见 §0-1，保持不动。）

**能否基于文档快照：能，而且很合适。** 文档就是完整状态，`loadDocument(上一份)` 即撤销；GLB 模板已缓存
（`Character.load` 用 `_templates` + SkeletonUtils.clone），重建只剩克隆 + 摆姿，预计十几个角色以内是毫秒～几十毫秒级。

方案要点：
- 栈里存 JSON 字符串；和栈顶相同不 push（天然过滤"点了但没改"）。
- 快照时机：每个用户操作**结束**时 —— gizmo `dragging-changed → false`、滑条 `change`（松手）、
  按钮/菜单动作完成后、异步加载（加角色/群众/复制）完成后。
- 大资产：快照里把 `assets` 拆出来单独按 id 缓存，快照只存引用，避免 N 份 dataURL；栈上限 100 步。
- 撤销/重做后尽量保持选中（id 稳定，选中 id 仍存在就重新选上）。
- 撤销不动导演相机、不切视角模式（都是 C）。

## 7. 需要你决定的点

1. **撤销重做的入口**（因为没有现成 UI）
   - (a) 只加快捷键 ⌘Z / ⌘⇧Z（Windows Ctrl+Z / Ctrl+Y），不动布局 ← **推荐**，符合"不改布局"约束
   - (b) 再在顶栏加 ↶ ↷ 两个按钮（改布局）
2. **transform.scale 存什么口径**
   - (a) 相对素体自然尺寸的倍数（站立的素体 = [1,1,1]；角色内部 root.scale = 存值 × [baseScale·girth, baseScale, baseScale·girth]）
     ← **推荐**：文档与模型文件解耦，换模型 / 改档案高度后文档仍有效，AI 生成时也好写
   - (b) 原样存 root.scale（与面板「缩放」三栏显示的数一致，但数值依赖模型原始单位，如 Mixamo 的 0.01）
3. **内置全景存 url 还是 dataURL**：推荐 assets 条目允许 `url` 或 `dataURL` 二选一（§5）。
4. **导演相机视角**是否进文档
   - (a) 不进文档（纯 C）；导入后自动 frameSubjects ← 撤销时肯定不动它
   - (b) 存进 `meta.editorView: {pos, target}`，仅「导入场景 / 恢复上次场景」时应用，撤销忽略 ← **推荐**：
     打开存档能回到当时的取景，而且 selftest 的"截图 A = 截图 B"在导演视角下才有意义
5. **文档里 crowd 的 type 名**：按任务书写 `group`（代码里仍叫 Crowd）。若你更想保持 `crowd` 一致也行。
6. **名字计数器**（`_charSeq / _propCount / _camCount / _groupCount`，只用于起名）：导入后按已有名字把计数器推进，
   避免新建出第二个「角色A」。属于 B，不存。
