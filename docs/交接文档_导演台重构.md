## 1. 这是什么、要做成什么

`demo/` 是 CanvasFlow 里"3D 导演台"的原型：three.js + Vite、无框架，多角色 GLB 摆姿、几何道具、多机位、取景截图。
产出的画面是喂给后续 AI 视频生成节点的参考，所以要的是**位置、姿势、机位、时序准确**，不是画面好看。

目标（对齐竞品 liblib.tv 导演台的线上版）：

1. 换成关节人偶 BodyKun / BodyChan，默认站立 —— **已完成（阶段 A）**
2. 时间轴动画：角色位置/旋转/缩放、机位位置/旋转/FOV 可打关键帧；角色沿路径移动；7 种运镜预设；跟随/注视；播放时切主机位；导出 MP4
3. AI 一句话生成整个场景（含路径、运镜）；对话式修改；识图导入站位

## 2. 三条铁律（所有阶段都遵守）

1. **场景即数据**：界面上能看到的每个状态，场景文档（JSON）里都有对应字段，反之亦然。人改它、AI 写它、保存/撤销/导出都靠它。
2. **状态 = f(t)**：任意时刻的画面由 `evaluate(t)` 算出来，不靠逐帧累加。播放头随便拖、导出随便跳帧。
3. **预设都有稳定英文名**：`stand / walk / run / half_orbit / circle …`。这是 AI 的词汇表，起了就不改。

## 4. 已经定下来的设计决定（不要重新讨论）

### 4.1 姿势系统（阶段 A）
- `src/rig/jointSchema.js`：28 个语义关节，与模型无关；`min/max` 是**相对自然站立**的范围。
- `src/rig/profiles/*.js`：每个模型一份档案 `{ id, label, file, heightM, joints, neutralOffset }`。
  `joints[key] = { bone, axis, sign }`，**axis 是身体坐标系**（X 左 / Y 上 / Z 前 / `twist` 自转），加载时换算成骨头局部轴，所以与骨头 roll 无关，换 Mixamo 骨骼的模型基本不用校准。
- 零点 = 自然站立：每轴角度 = `sign × (neutralOffset[key] + values[key])`，**按关节角度相加**再按 schema 顺序旋转（不是先乘一个偏移四元数）。`stand` 预设为空；`tpose` 是特殊预设，values = −neutralOffset。
- `Pose`：`{ values }`，可 clone / toJSON / fromJSON，**不做插值**（时间轴不打姿态关键帧，见 4.3）。
- 加载校验：缺关节 → toast + console.warn，对应滑条禁用；角色仍可添加移动。
- `Character._ground()` 摆姿后自动贴地；已预留 `autoGround` 开关（默认 true）。**阶段 C 做步行时必须关掉它**（抬脚时最低骨头逐帧变化会让模型上下跳）。
- 新增人偶流程：复制一份档案 → 填 file/height → 打开 `calib.html?profile=<id>` 看 28 格截图 → 方向反了改 `sign`/`axis`。详见 README。
- 资产规范：Mixamo 65 骨命名、T-pose 静止位、单位米、Y 向上、Apply Transforms、无材质无贴图无动画、GLB。源 .blend 在 `demo/_assets_src/`（不入库，派生体型要用）。

### 4.2 场景文档（阶段 B）
- 顶层键：`schema / meta / scene / assets / entities / paths / constraints / timeline`。后三者现在为空/默认，**只预留形状**。
- `schema: 'director-stage/0.1'`，`src/doc/migrate.js` 按版本逐级升级。
- 实体 `type`：`character / prop / camera / group`（代码里 Crowd 类不改名，文档里写 `group`）。
- id：8 位 base36 随机串，永不复用；名字计数器只用于起名，导入后按已有名字推进。
- `transform.scale` 存**相对素体自然尺寸的倍数**（站立素体 = [1,1,1]），不存 root.scale。
- **面板显示 = 文档口径**：Inspector 位置 / 旋转 / 缩放读写都经 `_docTransformOpts` 换算（角色落地 Y = 0、素体缩放 = 1），与导出 JSON、关键帧值逐项相等；面板输入不会因素体固有偏移把角色抬高。
- `character.body` 存体型 key（`male / female / …`），`pose: { preset, values }`，values 只存非 0。
- 群众成员作为 character 条目带 `parent: groupId`，transform 是相对组轴心的局部变换。
- 机位：存 `transform + fov + roll + lookAt`；**导入只应用 transform + roll**，lookAt 原样写回供面板显示，不重新瞄准。
- 全景：`assets[id] = { type:'image', name, url | dataURL }` 二选一；url 必须以 `./assets/` 开头；导出时丢弃未引用的 assets。
- 截图（shots）不进文档；`loadDocument` 清空走专用路径不碰 ShotManager；导入时清孤儿截图。
- 导演相机视角存 `meta.editorView`，仅导入/恢复存档时应用，撤销忽略。
- 校验器手写（不引 ajv），错误要能定位到字段；不合法一律拒绝加载。
- 撤销重做：文档快照栈（JSON 字符串、与栈顶相同不 push、上限 100），操作**结束**时记录（gizmo 松手、滑条 change、异步加载完成）；assets 按 id 单独缓存；入口 ⌘Z/⌘⇧Z + Dock 菜单两项。`loadDocument` 期间屏蔽 history 和自动保存，完成后记一份快照作为起点。
- 自动保存：防抖 1s 写 localStorage，超 4MB 不写并 toast；启动时有存档则 toast 提供"恢复上次场景"，不自动恢复。

### 4.3 时间轴（阶段 C 已实现；D–F 沿用）
- 轨道只有：角色 / 道具 / 组 位置 · 旋转 · 缩放，机位位置 · 旋转 · FOV（机位不打 scale）。**不做姿态关键帧**。
- 文档形状见 `src/doc/schema.js` 顶部注释：`timeline { duration, fps, mainCameraId, tracks[] }`、`paths[]`、`constraints[]`；
  id 与实体同一命名空间；值的口径与 `transform` 相同。**keys 可为空**（先加轨道再打键的中间状态，evaluate 里是 no-op，但仍占"同实体同属性一条"的名额）。
- 同一实体同一 property 最多一条轨道；有路径的实体不能再有 pos 轨道（直接拒绝）；每个实体最多一条路径；群众成员不能单独有路径（整组沿路径）。
- **手动值与动画值共存**：Timeline 有 idle / active 两态。active 时对被驱动实体记 `base`（transform 欧拉 / fov / pose.values），
  `evaluate(t)` 每次从 base 出发；`stop()` 写回 base；active 期间 `toDocument()` 与撤销快照都导出 base（`timeline.baseOf`）。
  gizmo / 面板在 active 期间的修改按下一条「编辑归属」处理。
- **active 期间编辑的归属（阶段 D 定，`Timeline.editAt`）**：一次操作**结束**时（gizmo 松手、输入框 change、轴标签 / 滑条松手）
  调 `app.edited(ent, props)`，props 为改过的属性（gizmo 按当前模式给 pos / rot / scale，面板按字段给）：
  - 该属性此刻被**路径或生效中的约束**驱动（路径 → pos，orient=tangent 时还有 rot；follow → pos + rot；lookAt → rot）→ 不记，toast「位置由路径驱动，修改未记录」；
  - **有轨道**（含空轨道）→ `setKey(当前时刻)`，同刻已有键则覆盖、沿用其 ease，否则 linear；
  - **无轨道** → 「自动打键」开：新建轨道 + 写键（一次撤销）；关：记进 base（改手动值）；
  - 姿势 / 颜色等非轨道属性（props 省略）→ `refreshBase`（改手动值）。
  本次打键的属性**不写进 base**：停止后回到原手动值。键值口径 = 文档口径（`timeline.valueOf(ent, prop)`，复用 `_transformJSON`，UI 不另写换算）。
  idle 时 edited 什么都不做（root 就是手动值）。gizmo 拖动开始时暂停播放（否则会被逐帧求值覆盖）。
  「自动打键」是会话偏好（播放条红点，默认关，存 localStorage，不进文档）。
- `evaluate(t)` 固定顺序：关键帧轨道 → 路径轨道（含步态）→ 约束。约束里 follow 先于 lookAt。纯函数：播放到 t 与直接 seek(t) 逐数值相同（验收实测差 0）。
- 旋转插值用四元数，位置 / 缩放 / FOV 线性；ease ∈ linear / smooth / step，作用于"从该键出发"的那一段；内部时间用秒，fps 只影响 `snap` 和导出。
- 路径是源头（`PathTrack` 持曲线 + 时长），不烘成关键帧；centripetal Catmull-Rom + 弧长表；speed linear / smooth；orient tangent（只换 yaw）/ keep；
  start 前停在起点、结束后停在终点。角色 / 组路径点 y = 地面高度。
- **路径停顿 stops（收尾 1）**：Path 可选字段 `stops`（停顿顶点索引，升序、不含首尾，闭合路径可到 n−1）与 `stopTimes`
  （到达各停顿的时刻，相对 start，与 stops 等长、递增、在 (0, duration) 内；缺省 = 按弧长比例分配）。schema 版本不升，
  两个字段缺省时文档与之前逐字段相同。有 stops 时 Path 在停顿顶点处断成几段**独立的** Catmull-Rom（停顿处允许折角，
  所以推镜头那段是严格直线），每段各自 smoothstep 缓入缓出（**无论 speed**，停顿处速度为 0；speed 只作用于无停顿的路径）。
  维护规则（`pathGen.fitStops` 等，updatePath / setPath 自动执行）：插入 / 删除顶点、反向时索引跟着走；patch 改了顶点数又没给
  stops → 去掉；越界的去掉；改 duration 没给 stopTimes → 按比例缩放；空 stops 删字段。重新绘制（setPath 替换）停顿作废。
  `appendMove` 在接缝加停顿、stopTimes 按名义时长（推 3 s + 半环绕 5 s → [3]），所以运镜段列表的起止时刻是真的。
  stopTimes 是任务说明之外加的字段（产品确认：只存索引做不到"推 3 s 就是 3 s"）。
- **起步平滑转身（收尾 1）**：orient=tangent 时 yaw = 手动朝向 yaw（进入路径前的状态：base / rot 轨道）→ 切线 yaw 的最短方向插值，
  进度 = 已走路程 ÷ 0.6 m（`PathTrack.TURN_IN_DIST`）。按路程不按时间，仍是纯函数；t ≤ start 时朝向 = 手动朝向。
- **lookAt 入场 / 退场混合（收尾 1）**：start > 0 的 lookAt 在 [start, start+0.5 s] 内从"约束前朝向"（关键帧 / 路径 / follow 之后）
  slerp 到注视朝向（进度 smoothstep）；end 非空时 [end−0.5 s, end] 内转回约束前朝向；start 为 null / 0 直接全量生效。
  接力：同一机位上一条 lookAt 的 end 恰好等于这条的 start 时，上一条不退场，这一条从上一条的注视朝向转过来（不回摆）。
- **步态（Locomotion，产品确认过的实现）**：相位按路程（走跑混合区按 ∫v/周期长度 积分）；周期长度 **走 0.8×身高**（说明原为 1.3，太长）/ 跑 1.9×身高；
  ≤1.8 m/s 纯走、≥2.6 纯跑；w = clamp(v/0.5) 与原姿势**整身**混合，速度 0 即原姿势。腿用"脚踩点 + 两段腿 IK"：支撑脚钉地（弧形脚底滚动接触），
  摆动脚 sin² 抬脚弧线，骨盆 = 双腿可达高度在相位域"滑动最小 + 均值"平滑，介入期间 autoGround=false。组沿路径时成员一起走，相位按 frac(i·0.618) 错开。
  改步态参数后必跑 `selftest collide`（含走 / 跑 8 相位）和 `selftest anim`。
- **约束**：lookAt 对准注视点并保留机位 roll；follow 为**刚性跟随**（位置 = 锚点 + Ry(yaw)·offset，朝向 = Ry(yaw) × 机位原朝向），覆盖机位的 pos 轨道 / 路径。
  注视点：角色 = 脚底上方半个身高（不随步态抖），道具 = 包围盒中心，组 = 成员平均。
- 删除实体连带删除引用它的轨道 / 路径 / 约束 / mainCameraId（同一次撤销）；打组 / 解组时相关成员的 pos/rot/scale 轨道与路径删除（坐标系变了）。
- **路径起点规则（阶段 E 定）**：五种绘制方式的首点 = 实体当前**手动值**（active 时取 base，不取动画瞬时值）投到地面
  （`PathTool.startPoint`），所以创建后 t=0 位置不跳。拖动首点后起点不再跟随实体；Inspector「起点对齐当前位置」把首点拉回。
  组的路径点同样取地面高度（与角色一致）。orient=tangent 时起步按路程平滑转向（见上「起步平滑转身」）。
- 阶段 F：7 种运镜预设 = 路径生成器 + 注视约束；追加拼接 = 路径首尾相接。整段视频只有一个主机位（`mainCameraId`），详见 4.6。
- **主机位播放（阶段 F）**：机位视角下时间轴 active（播放或拖播放头）→ 视口透过 `mainCameraId`（未设 → 当前机位 + 视口左上角提示）；
  idle → 回到当前机位（`activeCameraId`）。导演视角不切换。实际出画的机位 = `app.povCameraId`（截图也归它）。
  运镜期间的优先级不新发明：关键帧 → 路径 → 约束（follow 先于 lookAt），运镜生成的 lookAt 覆盖机位的 rot 轨道。
- 阶段 G 导出：WebCodecs 逐帧离线渲染，第 i 帧 = `evaluate(t0 + i/fps)`；名牌进画面（3D 精灵）。详见 4.7。

### 4.4 时间轴面板（阶段 D 已实现；E–F 在其上扩展）
- 布局：`#timeline` 在 main 下方，展开 220px / 折叠 36px（只剩播放条）；Dock「时间轴」按钮切换；窗口高 < 900px 默认折叠。
  折叠 / 自动打键 / 吸附 / 循环存 localStorage（键 `director-stage.timeline`），不进文档。
- **面板不持有文档状态**：行在 timeline 'change' 时按 `toJSON()` 全量重建（同一同步流程合并为一次，绘制前完成）；
  播放头在 'tick' 时只改 transform；横向位置是 CSS 变量 `--t × --pps`，缩放只改 `--pps`。所有写操作走 timeline API。
- **列出所有实体**（收尾 1；顺序同大纲，成员紧跟其组）：没有动画数据的只有表头（灰字 `is-bare`）+ 右侧「◇ 打键」（= Inspector 位置菱形，
  共用 `animState.toggleKey`）；空轨道为灰色虚线行；路径 = 绿条 + 起止菱形，约束 = 紫条（null 端铺满并显示「全程」）。
- 旋转键在面板上**只显示菱形，不显示数值**；多选拖键**按按下的那颗吸附**，其余保持相对间距，整体夹在 [0, 时长]。
  拖键松手时 removeKey + setKey（同步完成 = 一次撤销），落到已有键的时刻即覆盖；⌥ 拖 = 复制。
- 路径条：拖中间 / 起点 = 改 start（时长不变），拖终点 = 改 duration；约束条只拖两端（中间拖动不做）。
- `Del` 有选中键时删键（捕获阶段拦截），点面板外取消选键，之后 `Del` 照常删实体；`Esc` 只在 active 时拦截（= stop）。
- Inspector：位置 / 旋转 / 缩放 / 视野栏标题旁菱形（无轨道空心灰 / 有轨道无键空心亮 / 当前时刻有键实心 accent；被路径驱动的属性禁用）。
  **机位面板没有旋转栏，旋转菱形挂在「注视坐标」栏**（它决定机位朝向）。idle 时点菱形 = 在 0 秒打键并 seek(0)。
  数值随 tick 刷新（rAF 节流），被驱动属性灰字；active 时顶部提示条。播放中点进文本 / 数字输入框或按下轴标签 → 暂停（同 gizmo，收尾 1），不自动恢复。
- Inspector 路径段对**任何有路径的实体**显示（含机位）；阶段 E 起角色 / 道具 / 组无路径时也显示段头与「新建路径 ▾」（见 4.5）。
  约束段只在机位面板：注视（无 / 实体含群众成员 / 自定义点）、跟随（实体 + 偏移，新建时默认偏移 = 当前相对位置，机位不跳），各自 start/end（清空 = 全程）。
  每个机位每种约束面板只显示第一条。
- 调试句柄：`window.__timelinePanel`（selftest tl 用）。

### 4.5 路径工具（阶段 E 已实现；F 的运镜预设复用生成器）
- 生成器 `src/anim/pathGen.js`（纯函数，文档口径 `[x,y,z]`，点的 y 由调用方给）：`line / arc / toward / simplify / defaultDuration`，
  另有 `polar`（arc 反算）、`pathLength`（复用 Path 弧长表，与求值同一条曲线）。arc 角度从 +X 起、俯视逆时针为正，`|sweep| ≥ 360` 闭合且不重复首点；
  toward 按水平距离停在目标前 0.8 m，太近返回 null；defaultDuration = 长度 ÷ 1.3 m/s 向上取 0.5 s、最短 1 s。**生成器参数不进文档**，文档只存 points。
- 五种绘制方式（`PathTool`，AI 词汇表 `points / freehand / line / arc / toward`）：点击落点（Enter / 双击结束，Backspace 退点）、
  手绘（每 2 cm 采样，松手 simplify(0.05)，首点替换为当前位置）、直线、环绕（中心可吸附实体：角色 / 组取脚底，其余取包围盒中心；
  半径 / 起始角由当前位置得出，sweep 默认 180°，每 22.5° 一段）、走到（点实体，或 ⇧ 点地面）。
  新路径 `start = 当前时刻（idle 0）`、`duration = defaultDuration`、`speed = smooth`、`orient = tangent`。
- 入口：Dock「路径」按钮 + Inspector 路径段「新建路径 ▾ / 重新绘制 ▾」（等价）。角色 / 道具 / 组；阶段 F 起含机位（见 4.6）。
- 冲突（确认 toast，不点即取消）：已有 pos 轨道 →「删除并继续」；已有路径 →「替换」（保留 start / speed / orient，duration 按新长度重算）。
  删除 / 替换在**绘制完成时**与写入同一同步流程执行（一次撤销），绘制中 Esc 文档不变。
- 绘制态：OrbitControls 左键动作置空，**⌥ + 左键拖 = 环绕**（产品确认）；右键平移、滚轮缩放不变；gizmo 隐藏、视口点选暂停；顶部提示条；
  换选中 / 切机位视角即取消。
- 可视化 `PathOverlay`（挂在 stage.world 下，点 = 局部坐标）：Line2 等宽线（选中 2px，其它 1px 50% 透明），每米 64 段、上限 2000 段，抬高 1 cm；
  选中实体的路径另画顶点球（固定屏幕 ~10px）、起点三角、终点方块、每 1 m 方向箭头（keep 不画）；播放亮点随 tick 移动。
  **机位视角下整体不显示**（产品确认）；截图 / 机位预览（withCleanRender）也隐藏。不持有文档状态。
- 顶点编辑 `PathEditor`（不进绘制态）：拖顶点（同高水平面投影，拖动中只改 overlay 预览，松手 updatePath 一次撤销，开始时暂停播放并隐藏 gizmo，Esc 回原位）、
  ⇧ 拖 = 整条平移、点线插入（按弧长求所在段，点在曲线上）、点他人路径线 = 选中该实体、Del 删顶点（删后 < 2 点拒绝）。
  命中优先级：顶点 > gizmo 轴 > 曲线 > 实体；Del 优先级：选中键 > 选中顶点 > 实体。
- Inspector 路径段：顶点数 / 总长 / 平均速度（> 2.6 m/s 标「跑」）、反向、起点对齐当前位置、按步速重算时长（慢走 0.8 / 走 1.3 / 快走 1.8 / 跑 3.5）、删除；
  选中中间顶点时「在选中顶点（N）处停顿」勾选（收尾 1，`PathOverlay.setSelectedVertex` 发 'pathVertex' 事件刷新面板）。
  环绕路径额外显示 半径 / 起始角 / 扫过角度（会话态 `app.pathMeta[pathId]`，不进文档），改动即重算 points、**保留 duration**；
  只有 points 仍等于参数生成结果时才显示（拖过顶点 / 刷新页面后退化为普通点集）。
- 路径写操作只有 `addPath / updatePath / removePath`；`src/anim/` 除新增 pathGen.js（E）/ cameraMoves.js（F）外未改动。

### 4.6 机位运镜（阶段 F 已实现）
- 生成器 `src/anim/cameraMoves.js`（纯函数，调 pathGen）：`cameraMove(name, { position, rot, roll, aim, params })` → `{ points, closed, duration, rotKeys }`；
  `appendMove(path, next)` 追加拼接；`lookAtWindows(lookAts, { subject, cut, start })` 算新段注视窗口如何并入。写入入口 `app.cameraMoves`（`src/app/CameraMoveTool.js`）。
- 词汇表（定了不改）：`push_in / pull_out / truck / crane / pan / half_orbit / circle`，参数 `amount / dir / sweep / subject / duration`。几何与默认值见 README 运镜表。
- **"距离 / 连线"一律取水平分量**（与"路径点 y = 机位高度（crane 除外）"一致）：推 / 拉的终点距离、横移的垂直方向都按水平面算。
- `truck` 的 left / right **以机位视角为准**（产品确认）；环绕 dir 以俯视为准（ccw = pathGen.arc 正方向）。默认 dir：truck left、crane up、环绕 ccw。
- 环绕每 11.25° 一段，开放弧两端在 ¼ 段处各加一点（Catmull-Rom 端点直线外推使端段偏离圆；5 m 半径均匀采样偏 1.4 cm，加点后 0.25 cm）。
- 带路径的运镜：`speed = smooth`、`orient = keep`、`start = 当前时刻（idle 0）`；pan 生成 rot 轨道两键（ease smooth）。
- **注视窗口（产品确认）**：每段的 lookAt 从该段开始，**最后一段一直保持到全程结束（end = null）**，运镜结束后不会把朝向跳回手动值；
  追加时上一段注视在新段开始处截断，同一主体连续两段合并为一条；pan 的注视从摇完那一刻开始（摇的过程不被注视覆盖）。
  应用时不改机位手动朝向：机位原本没对准主体的话，start > 0 的注视在开始后 0.5 s 内平滑转过去（收尾 1 的入场混合；start = 0 时第 0 帧就已对准）。
  追加的接缝写进路径 stops / stopTimes，两段之间真的停下、各段按名义时长走（4.3「路径停顿」）。
- 主体默认 = 离机位最近的角色（含群众成员），没有角色取最近的其他实体，什么都没有 = 机位前方 3 m 的点；注视点同 Constraint.aimPoint。
- 冲突（沿用 E）：已有 pos 轨道 →「删除并继续」；pan 遇到非运镜产生的 rot 键 →「替换」；pan 不能接在路径后（toast）。「清除运镜」= 删路径 + 该机位全部约束 + rot 轨道。
- 预设参数与段列表是会话态 `app.moveMeta[cameraId]`，每段记逆操作与写入后的签名（路径 + rot 键）；只显示签名仍与文档一致的前缀，
  所以拖过顶点 / 刷新后退化为普通路径，⌘Z 后段列表随之回退 / 恢复。只能删最后一段（按记录的逆操作还原，一次撤销）。
- 机位路径绘制：`PathTool.canDraw` 含机位；绘制平面 = 过机位手动位置的水平面；默认 `orient = keep`；「走到」对机位叫「推到」（stopDistance 1.5 m）。
- 运镜预览：`PathOverlay.setMovePreview(points)` 虚线；Inspector 机位面板段顺序 = 运镜 → 路径 → 约束。
- 顶部「机位视角」按钮不变，旁边标签：idle 灰字当前机位名，透过主机位时强调色「▶ 主机位 · 名字」（产品确认）；透过主机位时 gizmo 隐藏。

### 4.7 导出视频（阶段 G 已实现）
- **帧规则（产品确认）**：N = round((t1−t0)·fps)，第 i 帧 = `timeline.evaluate(t0 + i/fps)`，**不含终点**（3 s × 30 fps = 90 帧，视频时长 = 范围长度）。
- 出画机位：主机位 > 当前机位（`activeCameraId`）> 选中机位 > 第一个机位；一个都没有 →「请先添加机位」。
- 分辨率：宽高比 = 取景比例（`auto` = 16:9），短边 720 / 1080 / 1440（**1440p 标「实验」，产品确认放出**），宽高取偶数。
- 离屏渲染 `OfflineRenderer`：主渲染器 → `WebGLRenderTarget`（4×MSAA, RGBA8）→ `readRenderTargetPixels` → 翻转 Y → `VideoFrame`（RGBA 缓冲）。不动主 canvas。
  **three r160 渲染到普通 RenderTarget 不做 toneMapping / sRGB 输出编码**：存储分配后把目标标成 `isXRRenderTarget`、纹理标 sRGB，
  让着色器走屏幕同一条路径（实测与 `stage.snapshot` 像素差 0）。升级 three 时要复查这一点（selftest export 验收 3 会报）。
- 编码：H.264，720p Baseline 6 Mbps / 1080p Main 12 Mbps / 1440p Main 20 Mbps，关键帧每 2 秒，`latencyMode:'quality'`；
  级别默认 3.1（`avc1.42001f`）/ 4.2（`avc1.4d002a`），帧宏块数超出时升到 4.2 / 5.0 / 5.1（21:9、1440p）。封装 `mp4-muxer`（`fastStart:'in-memory'`），唯一新增依赖。
- 导出会话：暂停 → 精灵名牌接管（DOM 名牌层隐藏）+ `beginCleanRender` → 逐帧求值渲染编码、每帧让出主线程 → 恢复播放头
  （导出前 active 则 `seek(原 t)`，idle 则 `stop()`）。不改文档、不记撤销、不触发自动保存。取消 = AbortError，不出文件。
- 名牌 `LabelSprites`：与 DOM 名牌同锚点（`labelAnchor`）、照抄 CSS 样式，名牌框**底边中点 = 锚点**（DOM 名牌框底在锚点上方约 10 px，精灵没有这段间距）；
  高 = 画面高 × 44/1080，scale 在 `onBeforeRender` 里按渲染相机 `P[1][1]` 算（所以任意分辨率 / 缩略图都按比例）。
  `withCleanRender`（截图、机位预览、导出）里显示精灵名牌，机位名牌不显示；平时视口仍是 DOM。「视口预览」开关在导出弹层里（会话态）。
- **名牌避让（收尾 1）**：`Labels.layoutLabels` 是 DOM 名牌与精灵名牌共用的布局函数 —— 按屏幕 x 排序、离相机近的先落位，
  远的与已落位矩形相交就上推（重叠高度 + 4 px）；没有重叠时 dy = 0、位置逐像素不变。精灵在每次 render × 相机由第一个精灵的
  onBeforeRender 算一次（1080 高的虚拟画面，4 px@1080p），结果写进 sprite.center.y。
- 洁净渲染改成可嵌套 `beginCleanRender / endCleanRender`（`_cleanDepth`，区间内 `_gizmoShouldShow` 恒 false），导出每帧再 `hideOverlays()` 一次。
- UI：Dock「场景 → 导出视频…」→ `ExportModal`。无 WebCodecs 时菜单项置灰、点击提示。导出中 `body.exporting` 锁住界面；
  弹层的 window 捕获键盘监听必须先于时间轴面板注册（`main.js` 里先创建），否则时间轴的 Esc/Space 先吃掉按键。

### 4.8 AI 生成（阶段 H 已实现）
- **模型不写场景文档，只写高层操作 ops**（`src/ai/ops.js`，18 种：clear / scene / add_character / add_prop / add_camera / add_group /
  add_crowd / remove / move / set_pose / set_path / clear_path / camera_move / clear_moves / look_at / follow / keyframe / timeline）。
  实体一律按名字引用；生成新场景 = clear + ops，修改 = 对当前场景的 ops（补丁），识图 = 只允许 clear / scene / add_character /
  add_prop / add_camera / move 且姿势固定站立。三种能力一条管道。
- **词汇表只从代码来**（`src/ai/vocab.js`）：BODY_TYPES、PROP_KINDS、POSE_PRESETS、cameraMoves 的预设 / 参数 / 方向、PathTool.PATH_MODES
  去掉 freehand、schema 的 ease / speed / orient / property / 约束 / 比例。只补中文解释（按枚举值做键，单测断言键集合相等）。
  校验器、提示词、README（`npm run docs:ai` 生成的标记块，单测断言一致）三处同一来源。
- **管道**：`validateOps`（结构 / 枚举 / 名字引用 / 范围，错误形如 `ops[2].preset 未知运镜 "orbit"，可选 …`）→ `compileOps` 在
  `toDocument()` 拷贝上逐条执行（全部用 `src/doc/edit.js` 纯函数，与界面操作同一份）→ `schema.validate` → `loadDocument`（pruneShots）
  → `history.capture()`（一次 AI 应用 = 一步撤销）。任何一步失败返回错误、场景不变。
- **重试回路**（`agent.js`）：错误原文作为下一轮用户消息「请修正以下错误后重新输出完整 ops」，最多重试 2 次；都失败 toast 前 3 条。
  修改模式遇空场景自动按生成处理。对话记录只在会话态（`app.ai.turns`）。
- **ops 语义（实现时定的，提示词里写明）**：yaw = rot.y（度），**0 = 面朝 +Z**（任务说明草稿写的 −Z 与代码不符，以代码为准）；
  clear 清实体与动画、保留天空 / 地面 / 比例 / 全景；camera_move 不带 `append: true` 时先清该机位旧运镜；look_at / follow 替换同类约束，
  follow 默认偏移 = 当前相对位置；set_path 的路径从实体当前位置出发、已有路径则替换（保留 start / speed / orient，同界面）；
  move 机位只改 pos 并重新对准原注视点；组成员不能单独 move / set_path / keyframe；重名新建加数字后缀并记入回执 renames；
  生成 / 识图没设主机位时自动取第一个有运镜的机位（回执 warning）；add_camera 默认 fov 40，场景没有当前机位时设为当前机位。
- **文档里的几何**：AI 新建的实体还没有场景对象，注视点 / 锚点按文档推算（`apply.js docAimPoint`：角色 = 脚底 + 半身高，
  道具 = `Prop.propLocalCenter` 几何中心，组 = 成员平均），与 `Constraint.aimPoint` / `PathTool.anchorOf` 同口径。
- set_path 的 points 写法可带 `stops`（points 下标，+1 映射为路径顶点索引；只能用于 points 写法，越界定位报错）（收尾 1）。
- 自动取景避开抽屉（收尾 1）：AiPanel 开合时记 `app.frameInsetRight`（视口右边 − 抽屉左边，关了 0），`frameSubjects` 传给
  `CameraRig.frameAll({ insetRight })`：按剩余宽度取景、主体居中在左侧，再逐个检查包围盒（角色骨骼盒）投影不够就拉远。insetRight = 0 时与之前完全相同。
- **模型接口**（`provider.js`）：OpenAI 兼容 `/chat/completions`（fetch，`response_format: json_object`，不支持时自动去掉），
  图片走 `image_url` data URL；设置只存 localStorage `director-stage.ai`。`MockProvider` 只匹配用户输入那一段，selftest 用。
- **界面**（`ui/AiPanel.js`）：视口右侧抽屉，Dock 最右「AI」开合（打开时 Dock 左移）。生成模式发送前确认清空；
  「撤销这一轮」= history.undo，只在这一轮之后没有别的改动时可点。
- **第 2 步重构**：界面入口（App.addCharacter / addCrowd / groupCharacters、PathTool._commit、CameraMoveTool.commit / clear）改为在
  文档拷贝上调 `edit.*` 再建对象 / `Timeline.commitAnim` 一次提交。打组轴心仍取成员 root 世界中心（以 pivot 传入），
  成员旋转按 `Object3D.attach` 以往的结果规整欧拉表示，界面行为与重构前一致（A/B 文档对比只差 ≤ 1e-6 舍入）。

## 7. 协作方式（这套流程运转得很好，保持）

- 产品侧（用户）不写代码。规划者（Claude 对话）出**任务说明**；执行者（Claude Code，在终端）按说明做。
- 任务说明的固定格式：背景 → 要解决的问题 → 目标架构 → 分步执行（每步一个 commit）→ 验收标准 → 约束。
- 执行者遇到说明没覆盖的决策，**停下来列选项问**，不自行猜。已经发生过三次（旋转叠加顺序、BODY_TYPES 默认项、状态盘点五个决定），都按此处理。
- 执行者可以在有充分理由时超出任务说明（阶段 A 把关节轴改成身体坐标系、重做预设），但要在 commit message 里写清理由。
- 每个阶段开始前，规划者先看上一阶段的产物（commit、截图、文档）再写下一份任务说明。

## 8. 已知问题 / 注意事项

- 关节人偶是分块网格，髋、肩大角度旋转会露缝——手办本身的特性，不是 bug。
- 手指 15×2 根骨头有权重但没有滑条；Spine2 权重极少，弯腰靠 Spine1。
- `tall/small/broad/slim` 现在是 male 按身高/围度拉伸，真实体型模型等阶段 I 从 `_assets_src/` 派生。
- 导出视频只支持 Chrome/Edge（WebCodecs），Safari / Firefox 菜单项置灰；没做 WebM 回退、音频、字幕、水印。
- 导出期间视口仍按导演相机实时渲染（看到的是被求值的场景，不是成片）；成片画面只在弹层进度里体现，没有逐帧预览图。
- 1440p 在集成显卡上可能因显存 / 编码器能力失败（失败时 toast 报错）；headless swiftshader 下 1080p 约 6 帧/秒（5 s 示例 26 s），真机 GPU 快得多。
- 精灵名牌框底边贴在锚点上（头顶上方 16 cm 处），比 DOM 名牌低约 10 px；截图 / 导出 / 视口预览三处一致。
- 名牌避让只往上推：很多人站成一列时上面的名牌可能推出画面顶边；DOM 名牌固定 CSS 尺寸、精灵按画面高等比，所以两者推开的像素数在不同窗口大小下不完全相同（规则相同）。
- 截图现在带名牌（之前 DOM 名牌截不进去）；原 e2e 没有截图基线比对，所以没有需要更新的基线。
- 步态只在矢状面解 IK：直线上不打滑，急转弯路径上支撑脚会有少量滑动；跑步没有腾空上抬（骨盆只按可达高度下沉）。
  收尾 1 试过「朝向取 s ± 0.25 m 切线平均」：90° 折角（3 m + 3 m、5 s 匀速）支撑脚水平滑动量 105.73 cm → 106.11 cm（贴地阈值 3 mm；
  0.5 mm 阈值 69.24 → 69.93 cm），没有减少 —— 一个拐角的总转角不变，平均只是把转身摊开，站立期占比不变，脚跟着身体转的量也不变。
  已回退。真要改需要按支撑脚锁定朝向（支撑期内脚的 yaw 钉住、只在摆动期转），属于步态重做。
- 步态与群众成员按组的速度 / 缩放计算；成员各自的缩放差异只影响相位，不单独调整步幅。
- "生成画布节点"（导出的视频接回 CanvasFlow 画布）和"虚拟相机（手机扫码手持录运镜）"是另两条线，不在本路线内；后者本质是从外部喂一串机位关键帧，阶段 C 的接口能接。
- active 期间在 Inspector 输入框里逐字输入时画面实时变化，但只在 change（回车 / 失焦）时归属一次（播放中聚焦输入框 / 按轴标签会先暂停）。
- 环绕三参数是会话态（`app.pathMeta`），刷新页面 / 拖过顶点后退化为普通点集，编辑框消失——有意为之（生成器参数不进文档）。
- 顶点拖动在顶点所在的水平面上进行（路径点同高），不支持拖高度；路径不能吸附到其他路径、不能调曲线张力（任务说明列为不做）。
  分段调速只有 stops（停顿 + 各段到达时刻）这一种：有停顿的路径每段都缓入缓出，不能「匀速经过某顶点」。
- 闭合路径「反向」后，原来停在最后一个顶点的停顿会落到首点上而被去掉（反向本身会把首点换成原来的末点，这是之前就有的行为）。
- 顶点球优先于 gizmo：首个顶点与角色脚下的 gizmo 中心重合，点中顶点时拖的是顶点（gizmo 三轴仍可用）。
- 手绘首点被替换为实体当前位置：若从远离角色的地方开始画，开头会有一段从角色连过去的线。
- 拖键 / 删多键是逐个调用 removeKey / setKey，每次都整份校验；几百个键一起拖会有可感知的停顿（100 键内无感）。
- 竞品参考：liblib.tv 导演台。实测要点：一句话生成整场景（含编组、路径、半环绕运镜、天空）；AI 识图导入站位；24 个姿势预设；轨道为 位置/旋转（角色）、位置/焦点/视角（机位）；路径蓝线球形顶点可拖；播放时角色切走路。
- 运镜参数 / 段列表是会话态：刷新页面、拖过顶点、手动改了路径后段列表消失，路径退化为普通路径（仍可「追加」）。
- 运镜的"距离"按水平面算；主体在机位正上 / 下方时推、拉、横移无法确定方向（提示错误）。
- 主体在运动时（例如沿路径走的角色），运镜的几何按应用那一刻主体的位置生成（环绕圆心不跟着走）；注视约束本身是实时跟随的。
- 透过主机位时 gizmo 隐藏，Inspector 仍可改数值；播放中在大纲点别的机位只改「当前机位」，停止后才切过去。
- AI：真实模型尚未冒烟（没有 key），自动验收全部用 MockProvider；不同模型对 yaw / 坐标的理解可能有偏差，需要按冒烟结果调范例。
- AI：浏览器直连模型接口，部分服务商不允许跨域（CORS）调用，需要换支持浏览器调用的接口或自己加一层代理。
- AI：识图只靠模型看图写坐标，站位是近似的；机位只推断方向（高 1.4 m、距离约 3 m）。
- AI：群众（add_crowd）成员名字由场景计数器起，同一批 ops 里不能引用新群众的成员；组成员不能单独移动 / 画路径。
- AI：执行期第一处错误即停（后面的 op 可能依赖它），所以一轮里同时有多处执行期错误时只报第一处；校验期错误会全部列出。
