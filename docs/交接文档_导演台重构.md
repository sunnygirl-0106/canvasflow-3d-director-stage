## 1. 这是什么、要做成什么

`demo/` 是 CanvasFlow 里"3D 导演台"的原型：three.js + Vite、无框架，多角色 GLB 摆姿、几何道具、多机位、取景截图。
产出的画面是喂给后续 AI 视频生成节点的参考，所以要的是**位置、姿势、机位、时序准确**，不是画面好看。

目标（对齐竞品 liblib.tv 导演台的线上版）：

1. 换成关节人偶 BodyKun / BodyChan，默认站立 —— **已完成（阶段 A）**
2. 时间轴动画：角色位置/旋转/缩放、机位位置/旋转/FOV 可打关键帧；角色沿路径移动；7 种运镜预设；跟随/注视；播放时切主机位；导出 MP4
3. AI 一句话生成整个场景（含路径、运镜）；对话式修改；识图导入站位

## 2. 三条铁律（所有阶段都遵守）

1. **场景即数据**：界面上能看到的每个状态，场景文档（JSON）里都有对应字段，反之亦然。人改它、AI 写它、保存/撤销/导出都靠它。
2. **状态 = f(t)**：任意时刻的画面由 `evaluate(t)` 算出来，不靠逐帧累加。播放头随便拖、导出随便跳帧。
3. **预设都有稳定英文名**：`stand / walk / run / half_orbit / circle …`。这是 AI 的词汇表，起了就不改。

## 4. 已经定下来的设计决定（不要重新讨论）

### 4.1 姿势系统（阶段 A）
- `src/rig/jointSchema.js`：28 个语义关节，与模型无关；`min/max` 是**相对自然站立**的范围。
- `src/rig/profiles/*.js`：每个模型一份档案 `{ id, label, file, heightM, joints, neutralOffset }`。
  `joints[key] = { bone, axis, sign }`，**axis 是身体坐标系**（X 左 / Y 上 / Z 前 / `twist` 自转），加载时换算成骨头局部轴，所以与骨头 roll 无关，换 Mixamo 骨骼的模型基本不用校准。
- 零点 = 自然站立：每轴角度 = `sign × (neutralOffset[key] + values[key])`，**按关节角度相加**再按 schema 顺序旋转（不是先乘一个偏移四元数）。`stand` 预设为空；`tpose` 是特殊预设，values = −neutralOffset。
- `Pose`：`{ values }`，可 clone / toJSON / fromJSON，**不做插值**（时间轴不打姿态关键帧，见 4.3）。
- 加载校验：缺关节 → toast + console.warn，对应滑条禁用；角色仍可添加移动。
- `Character._ground()` 摆姿后自动贴地；已预留 `autoGround` 开关（默认 true）。**阶段 C 做步行时必须关掉它**（抬脚时最低骨头逐帧变化会让模型上下跳）。
- 新增人偶流程：复制一份档案 → 填 file/height → 打开 `calib.html?profile=<id>` 看 28 格截图 → 方向反了改 `sign`/`axis`。详见 README。
- 资产规范：Mixamo 65 骨命名、T-pose 静止位、单位米、Y 向上、Apply Transforms、无材质无贴图无动画、GLB。源 .blend 在 `demo/_assets_src/`（不入库，派生体型要用）。

### 4.2 场景文档（阶段 B）
- 顶层键：`schema / meta / scene / assets / entities / paths / constraints / timeline`。后三者现在为空/默认，**只预留形状**。
- `schema: 'director-stage/0.1'`，`src/doc/migrate.js` 按版本逐级升级。
- 实体 `type`：`character / prop / camera / group`（代码里 Crowd 类不改名，文档里写 `group`）。
- id：8 位 base36 随机串，永不复用；名字计数器只用于起名，导入后按已有名字推进。
- `transform.scale` 存**相对素体自然尺寸的倍数**（站立素体 = [1,1,1]），不存 root.scale。
- `character.body` 存体型 key（`male / female / …`），`pose: { preset, values }`，values 只存非 0。
- 群众成员作为 character 条目带 `parent: groupId`，transform 是相对组轴心的局部变换。
- 机位：存 `transform + fov + roll + lookAt`；**导入只应用 transform + roll**，lookAt 原样写回供面板显示，不重新瞄准。
- 全景：`assets[id] = { type:'image', name, url | dataURL }` 二选一；url 必须以 `./assets/` 开头；导出时丢弃未引用的 assets。
- 截图（shots）不进文档；`loadDocument` 清空走专用路径不碰 ShotManager；导入时清孤儿截图。
- 导演相机视角存 `meta.editorView`，仅导入/恢复存档时应用，撤销忽略。
- 校验器手写（不引 ajv），错误要能定位到字段；不合法一律拒绝加载。
- 撤销重做：文档快照栈（JSON 字符串、与栈顶相同不 push、上限 100），操作**结束**时记录（gizmo 松手、滑条 change、异步加载完成）；assets 按 id 单独缓存；入口 ⌘Z/⌘⇧Z + Dock 菜单两项。`loadDocument` 期间屏蔽 history 和自动保存，完成后记一份快照作为起点。
- 自动保存：防抖 1s 写 localStorage，超 4MB 不写并 toast；启动时有存档则 toast 提供"恢复上次场景"，不自动恢复。

### 4.3 时间轴（阶段 C–F，已定原则）
- 轨道只有：角色位置/旋转/缩放，机位位置/旋转/FOV。**不做姿态关键帧**。
- 角色沿路径移动时姿势一律切成程序化步行（`Locomotion`）：相位 = 已走路程 ÷ 步幅（不是时间），速度超阈值切跑步；速度为 0 不介入，停下恢复原姿势。
- `evaluate(t)` 固定顺序：关键帧轨道 → 路径轨道 → 约束。跟随是约束，排最后，所以开跟随则运镜失效。
- 没打关键帧的属性保持手动值。
- 路径是源头（`PathTrack` 持曲线 + 时长），不烘成关键帧；时间轴上只显示起止两颗菱形。曲线用 Catmull-Rom。
- 旋转插值用四元数，位置/FOV 线性；内部时间用秒，帧率只影响吸附和导出。
- 7 种运镜预设 = 路径生成器 + 注视约束；追加拼接 = 路径首尾相接。整段视频只有一个主机位。
- 导出：WebCodecs 逐帧离线渲染，第 i 帧 = `evaluate(i/fps)`；名牌必须进画面（改 3D 精灵）。

### 4.4 AI 生成（阶段 H，已定原则）
- 提示词 = 场景文档 schema + 预设词汇表 + 范例 → 模型输出文档 → 校验 → 失败把错误喂回重试 → 加载。
- 对话式修改 = 模型输出补丁，不重写全文。识图导入 = 视觉模型只写数量/位置/朝向/机位方向。

## 7. 协作方式（这套流程运转得很好，保持）

- 产品侧（用户）不写代码。规划者（Claude 对话）出**任务说明**；执行者（Claude Code，在终端）按说明做。
- 任务说明的固定格式：背景 → 要解决的问题 → 目标架构 → 分步执行（每步一个 commit）→ 验收标准 → 约束。
- 执行者遇到说明没覆盖的决策，**停下来列选项问**，不自行猜。已经发生过三次（旋转叠加顺序、BODY_TYPES 默认项、状态盘点五个决定），都按此处理。
- 执行者可以在有充分理由时超出任务说明（阶段 A 把关节轴改成身体坐标系、重做预设），但要在 commit message 里写清理由。
- 每个阶段开始前，规划者先看上一阶段的产物（commit、截图、文档）再写下一份任务说明。

## 8. 已知问题 / 注意事项

- 关节人偶是分块网格，髋、肩大角度旋转会露缝——手办本身的特性，不是 bug。
- 手指 15×2 根骨头有权重但没有滑条；Spine2 权重极少，弯腰靠 Spine1。
- `tall/small/broad/slim` 现在是 male 按身高/围度拉伸，真实体型模型等阶段 I 从 `_assets_src/` 派生。
- 导出视频（阶段 G）只支持 Chrome/Edge（WebCodecs）。
- "生成画布节点"（导出的视频接回 CanvasFlow 画布）和"虚拟相机（手机扫码手持录运镜）"是另两条线，不在本路线内；后者本质是从外部喂一串机位关键帧，阶段 C 的接口能接。
- 竞品参考：liblib.tv 导演台。实测要点：一句话生成整场景（含编组、路径、半环绕运镜、天空）；AI 识图导入站位；24 个姿势预设；轨道为 位置/旋转（角色）、位置/焦点/视角（机位）；路径蓝线球形顶点可拖；播放时角色切走路。
