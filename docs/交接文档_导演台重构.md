## 1. 这是什么、要做成什么

`demo/` 是 CanvasFlow 里"3D 导演台"的原型：three.js + Vite、无框架，多角色 GLB 摆姿、几何道具、多机位、取景截图。
产出的画面是喂给后续 AI 视频生成节点的参考，所以要的是**位置、姿势、机位、时序准确**，不是画面好看。

目标（对齐竞品 liblib.tv 导演台的线上版）：

1. 换成关节人偶 BodyKun / BodyChan，默认站立 —— **已完成（阶段 A）**
2. 时间轴动画：角色位置/旋转/缩放、机位位置/旋转/FOV 可打关键帧；角色沿路径移动；7 种运镜预设；跟随/注视；播放时切主机位；导出 MP4
3. AI 一句话生成整个场景（含路径、运镜）；对话式修改；识图导入站位

## 2. 三条铁律（所有阶段都遵守）

1. **场景即数据**：界面上能看到的每个状态，场景文档（JSON）里都有对应字段，反之亦然。人改它、AI 写它、保存/撤销/导出都靠它。
2. **状态 = f(t)**：任意时刻的画面由 `evaluate(t)` 算出来，不靠逐帧累加。播放头随便拖、导出随便跳帧。
3. **预设都有稳定英文名**：`stand / walk / run / half_orbit / circle …`。这是 AI 的词汇表，起了就不改。

## 4. 已经定下来的设计决定（不要重新讨论）

### 4.1 姿势系统（阶段 A）
- `src/rig/jointSchema.js`：28 个语义关节，与模型无关；`min/max` 是**相对自然站立**的范围。
- `src/rig/profiles/*.js`：每个模型一份档案 `{ id, label, file, heightM, joints, neutralOffset }`。
  `joints[key] = { bone, axis, sign }`，**axis 是身体坐标系**（X 左 / Y 上 / Z 前 / `twist` 自转），加载时换算成骨头局部轴，所以与骨头 roll 无关，换 Mixamo 骨骼的模型基本不用校准。
- 零点 = 自然站立：每轴角度 = `sign × (neutralOffset[key] + values[key])`，**按关节角度相加**再按 schema 顺序旋转（不是先乘一个偏移四元数）。`stand` 预设为空；`tpose` 是特殊预设，values = −neutralOffset。
- `Pose`：`{ values }`，可 clone / toJSON / fromJSON，**不做插值**（时间轴不打姿态关键帧，见 4.3）。
- 加载校验：缺关节 → toast + console.warn，对应滑条禁用；角色仍可添加移动。
- `Character._ground()` 摆姿后自动贴地；已预留 `autoGround` 开关（默认 true）。**阶段 C 做步行时必须关掉它**（抬脚时最低骨头逐帧变化会让模型上下跳）。
- 新增人偶流程：复制一份档案 → 填 file/height → 打开 `calib.html?profile=<id>` 看 28 格截图 → 方向反了改 `sign`/`axis`。详见 README。
- 资产规范：Mixamo 65 骨命名、T-pose 静止位、单位米、Y 向上、Apply Transforms、无材质无贴图无动画、GLB。源 .blend 在 `demo/_assets_src/`（不入库，派生体型要用）。

### 4.2 场景文档（阶段 B）
- 顶层键：`schema / meta / scene / assets / entities / paths / constraints / timeline`。后三者现在为空/默认，**只预留形状**。
- `schema: 'director-stage/0.1'`，`src/doc/migrate.js` 按版本逐级升级。
- 实体 `type`：`character / prop / camera / group`（代码里 Crowd 类不改名，文档里写 `group`）。
- id：8 位 base36 随机串，永不复用；名字计数器只用于起名，导入后按已有名字推进。
- `transform.scale` 存**相对素体自然尺寸的倍数**（站立素体 = [1,1,1]），不存 root.scale。
- `character.body` 存体型 key（`male / female / …`），`pose: { preset, values }`，values 只存非 0。
- 群众成员作为 character 条目带 `parent: groupId`，transform 是相对组轴心的局部变换。
- 机位：存 `transform + fov + roll + lookAt`；**导入只应用 transform + roll**，lookAt 原样写回供面板显示，不重新瞄准。
- 全景：`assets[id] = { type:'image', name, url | dataURL }` 二选一；url 必须以 `./assets/` 开头；导出时丢弃未引用的 assets。
- 截图（shots）不进文档；`loadDocument` 清空走专用路径不碰 ShotManager；导入时清孤儿截图。
- 导演相机视角存 `meta.editorView`，仅导入/恢复存档时应用，撤销忽略。
- 校验器手写（不引 ajv），错误要能定位到字段；不合法一律拒绝加载。
- 撤销重做：文档快照栈（JSON 字符串、与栈顶相同不 push、上限 100），操作**结束**时记录（gizmo 松手、滑条 change、异步加载完成）；assets 按 id 单独缓存；入口 ⌘Z/⌘⇧Z + Dock 菜单两项。`loadDocument` 期间屏蔽 history 和自动保存，完成后记一份快照作为起点。
- 自动保存：防抖 1s 写 localStorage，超 4MB 不写并 toast；启动时有存档则 toast 提供"恢复上次场景"，不自动恢复。

### 4.3 时间轴（阶段 C 已实现；D–F 沿用）
- 轨道只有：角色 / 道具 / 组 位置 · 旋转 · 缩放，机位位置 · 旋转 · FOV（机位不打 scale）。**不做姿态关键帧**。
- 文档形状见 `src/doc/schema.js` 顶部注释：`timeline { duration, fps, mainCameraId, tracks[] }`、`paths[]`、`constraints[]`；
  id 与实体同一命名空间；值的口径与 `transform` 相同。**keys 可为空**（先加轨道再打键的中间状态，evaluate 里是 no-op，但仍占"同实体同属性一条"的名额）。
- 同一实体同一 property 最多一条轨道；有路径的实体不能再有 pos 轨道（直接拒绝）；每个实体最多一条路径；群众成员不能单独有路径（整组沿路径）。
- **手动值与动画值共存**：Timeline 有 idle / active 两态。active 时对被驱动实体记 `base`（transform 欧拉 / fov / pose.values），
  `evaluate(t)` 每次从 base 出发；`stop()` 写回 base；active 期间 `toDocument()` 与撤销快照都导出 base（`timeline.baseOf`）。
  gizmo / 面板在 active 期间的修改按下一条「编辑归属」处理。
- **active 期间编辑的归属（阶段 D 定，`Timeline.editAt`）**：一次操作**结束**时（gizmo 松手、输入框 change、轴标签 / 滑条松手）
  调 `app.edited(ent, props)`，props 为改过的属性（gizmo 按当前模式给 pos / rot / scale，面板按字段给）：
  - 该属性此刻被**路径或生效中的约束**驱动（路径 → pos，orient=tangent 时还有 rot；follow → pos + rot；lookAt → rot）→ 不记，toast「位置由路径驱动，修改未记录」；
  - **有轨道**（含空轨道）→ `setKey(当前时刻)`，同刻已有键则覆盖、沿用其 ease，否则 linear；
  - **无轨道** → 「自动打键」开：新建轨道 + 写键（一次撤销）；关：记进 base（改手动值）；
  - 姿势 / 颜色等非轨道属性（props 省略）→ `refreshBase`（改手动值）。
  本次打键的属性**不写进 base**：停止后回到原手动值。键值口径 = 文档口径（`timeline.valueOf(ent, prop)`，复用 `_transformJSON`，UI 不另写换算）。
  idle 时 edited 什么都不做（root 就是手动值）。gizmo 拖动开始时暂停播放（否则会被逐帧求值覆盖）。
  「自动打键」是会话偏好（播放条红点，默认关，存 localStorage，不进文档）。
- `evaluate(t)` 固定顺序：关键帧轨道 → 路径轨道（含步态）→ 约束。约束里 follow 先于 lookAt。纯函数：播放到 t 与直接 seek(t) 逐数值相同（验收实测差 0）。
- 旋转插值用四元数，位置 / 缩放 / FOV 线性；ease ∈ linear / smooth / step，作用于"从该键出发"的那一段；内部时间用秒，fps 只影响 `snap` 和导出。
- 路径是源头（`PathTrack` 持曲线 + 时长），不烘成关键帧；centripetal Catmull-Rom + 弧长表；speed linear / smooth；orient tangent（只换 yaw）/ keep；
  start 前停在起点、结束后停在终点。角色 / 组路径点 y = 地面高度。
- **步态（Locomotion，产品确认过的实现）**：相位按路程（走跑混合区按 ∫v/周期长度 积分）；周期长度 **走 0.8×身高**（说明原为 1.3，太长）/ 跑 1.9×身高；
  ≤1.8 m/s 纯走、≥2.6 纯跑；w = clamp(v/0.5) 与原姿势**整身**混合，速度 0 即原姿势。腿用"脚踩点 + 两段腿 IK"：支撑脚钉地（弧形脚底滚动接触），
  摆动脚 sin² 抬脚弧线，骨盆 = 双腿可达高度在相位域"滑动最小 + 均值"平滑，介入期间 autoGround=false。组沿路径时成员一起走，相位按 frac(i·0.618) 错开。
  改步态参数后必跑 `selftest collide`（含走 / 跑 8 相位）和 `selftest anim`。
- **约束**：lookAt 对准注视点并保留机位 roll；follow 为**刚性跟随**（位置 = 锚点 + Ry(yaw)·offset，朝向 = Ry(yaw) × 机位原朝向），覆盖机位的 pos 轨道 / 路径。
  注视点：角色 = 脚底上方半个身高（不随步态抖），道具 = 包围盒中心，组 = 成员平均。
- 删除实体连带删除引用它的轨道 / 路径 / 约束 / mainCameraId（同一次撤销）；打组 / 解组时相关成员的 pos/rot/scale 轨道与路径删除（坐标系变了）。
- **路径起点规则（阶段 E 定）**：五种绘制方式的首点 = 实体当前**手动值**（active 时取 base，不取动画瞬时值）投到地面
  （`PathTool.startPoint`），所以创建后 t=0 位置不跳。拖动首点后起点不再跟随实体；Inspector「起点对齐当前位置」把首点拉回。
  组的路径点同样取地面高度（与角色一致）。orient=tangent 时 t=start 朝向会转向首段切线（位置不跳，朝向不保证不转）。
- 阶段 F：7 种运镜预设 = 路径生成器 + 注视约束；追加拼接 = 路径首尾相接。整段视频只有一个主机位（`mainCameraId`，本阶段只存）。
- 阶段 G 导出：WebCodecs 逐帧离线渲染，第 i 帧 = `evaluate(i/fps)`；名牌必须进画面（改 3D 精灵）。

### 4.4 时间轴面板（阶段 D 已实现；E–F 在其上扩展）
- 布局：`#timeline` 在 main 下方，展开 220px / 折叠 36px（只剩播放条）；Dock「时间轴」按钮切换；窗口高 < 900px 默认折叠。
  折叠 / 自动打键 / 吸附 / 循环存 localStorage（键 `director-stage.timeline`），不进文档。
- **面板不持有文档状态**：行在 timeline 'change' 时按 `toJSON()` 全量重建（同一同步流程合并为一次，绘制前完成）；
  播放头在 'tick' 时只改 transform；横向位置是 CSS 变量 `--t × --pps`，缩放只改 `--pps`。所有写操作走 timeline API。
- 只列出**有动画数据**的实体（顺序同大纲，成员紧跟其组）；空轨道为灰色虚线行；路径 = 绿条 + 起止菱形，约束 = 紫条（null 端铺满并显示「全程」）。
- 旋转键在面板上**只显示菱形，不显示数值**；多选拖键**按按下的那颗吸附**，其余保持相对间距，整体夹在 [0, 时长]。
  拖键松手时 removeKey + setKey（同步完成 = 一次撤销），落到已有键的时刻即覆盖；⌥ 拖 = 复制。
- 路径条：拖中间 / 起点 = 改 start（时长不变），拖终点 = 改 duration；约束条只拖两端（中间拖动不做）。
- `Del` 有选中键时删键（捕获阶段拦截），点面板外取消选键，之后 `Del` 照常删实体；`Esc` 只在 active 时拦截（= stop）。
- Inspector：位置 / 旋转 / 缩放 / 视野栏标题旁菱形（无轨道空心灰 / 有轨道无键空心亮 / 当前时刻有键实心 accent；被路径驱动的属性禁用）。
  **机位面板没有旋转栏，旋转菱形挂在「注视坐标」栏**（它决定机位朝向）。idle 时点菱形 = 在 0 秒打键并 seek(0)。
  数值随 tick 刷新（rAF 节流），被驱动属性灰字；active 时顶部提示条。
- Inspector 路径段对**任何有路径的实体**显示（含机位）；阶段 E 起角色 / 道具 / 组无路径时也显示段头与「新建路径 ▾」（见 4.5）。
  约束段只在机位面板：注视（无 / 实体含群众成员 / 自定义点）、跟随（实体 + 偏移，新建时默认偏移 = 当前相对位置，机位不跳），各自 start/end（清空 = 全程）。
  每个机位每种约束面板只显示第一条。
- 调试句柄：`window.__timelinePanel`（selftest tl 用）。

### 4.5 路径工具（阶段 E 已实现；F 的运镜预设复用生成器）
- 生成器 `src/anim/pathGen.js`（纯函数，文档口径 `[x,y,z]`，点的 y 由调用方给）：`line / arc / toward / simplify / defaultDuration`，
  另有 `polar`（arc 反算）、`pathLength`（复用 Path 弧长表，与求值同一条曲线）。arc 角度从 +X 起、俯视逆时针为正，`|sweep| ≥ 360` 闭合且不重复首点；
  toward 按水平距离停在目标前 0.8 m，太近返回 null；defaultDuration = 长度 ÷ 1.3 m/s 向上取 0.5 s、最短 1 s。**生成器参数不进文档**，文档只存 points。
- 五种绘制方式（`PathTool`，AI 词汇表 `points / freehand / line / arc / toward`）：点击落点（Enter / 双击结束，Backspace 退点）、
  手绘（每 2 cm 采样，松手 simplify(0.05)，首点替换为当前位置）、直线、环绕（中心可吸附实体：角色 / 组取脚底，其余取包围盒中心；
  半径 / 起始角由当前位置得出，sweep 默认 180°，每 22.5° 一段）、走到（点实体，或 ⇧ 点地面）。
  新路径 `start = 当前时刻（idle 0）`、`duration = defaultDuration`、`speed = smooth`、`orient = tangent`。
- 入口：Dock「路径」按钮 + Inspector 路径段「新建路径 ▾ / 重新绘制 ▾」（等价）。仅角色 / 道具 / 组（机位路径在 F）。
- 冲突（确认 toast，不点即取消）：已有 pos 轨道 →「删除并继续」；已有路径 →「替换」（保留 start / speed / orient，duration 按新长度重算）。
  删除 / 替换在**绘制完成时**与写入同一同步流程执行（一次撤销），绘制中 Esc 文档不变。
- 绘制态：OrbitControls 左键动作置空，**⌥ + 左键拖 = 环绕**（产品确认）；右键平移、滚轮缩放不变；gizmo 隐藏、视口点选暂停；顶部提示条；
  换选中 / 切机位视角即取消。
- 可视化 `PathOverlay`（挂在 stage.world 下，点 = 局部坐标）：Line2 等宽线（选中 2px，其它 1px 50% 透明），每米 64 段、上限 2000 段，抬高 1 cm；
  选中实体的路径另画顶点球（固定屏幕 ~10px）、起点三角、终点方块、每 1 m 方向箭头（keep 不画）；播放亮点随 tick 移动。
  **机位视角下整体不显示**（产品确认）；截图 / 机位预览（withCleanRender）也隐藏。不持有文档状态。
- 顶点编辑 `PathEditor`（不进绘制态）：拖顶点（同高水平面投影，拖动中只改 overlay 预览，松手 updatePath 一次撤销，开始时暂停播放并隐藏 gizmo，Esc 回原位）、
  ⇧ 拖 = 整条平移、点线插入（按弧长求所在段，点在曲线上）、点他人路径线 = 选中该实体、Del 删顶点（删后 < 2 点拒绝）。
  命中优先级：顶点 > gizmo 轴 > 曲线 > 实体；Del 优先级：选中键 > 选中顶点 > 实体。
- Inspector 路径段：顶点数 / 总长 / 平均速度（> 2.6 m/s 标「跑」）、反向、起点对齐当前位置、按步速重算时长（慢走 0.8 / 走 1.3 / 快走 1.8 / 跑 3.5）、删除。
  环绕路径额外显示 半径 / 起始角 / 扫过角度（会话态 `app.pathMeta[pathId]`，不进文档），改动即重算 points、**保留 duration**；
  只有 points 仍等于参数生成结果时才显示（拖过顶点 / 刷新页面后退化为普通点集）。

## 7. 协作方式（这套流程运转得很好，保持）

- 产品侧（用户）不写代码。规划者（Claude 对话）出**任务说明**；执行者（Claude Code，在终端）按说明做。
- 任务说明的固定格式：背景 → 要解决的问题 → 目标架构 → 分步执行（每步一个 commit）→ 验收标准 → 约束。
- 执行者遇到说明没覆盖的决策，**停下来列选项问**，不自行猜。已经发生过三次（旋转叠加顺序、BODY_TYPES 默认项、状态盘点五个决定），都按此处理。
- 执行者可以在有充分理由时超出任务说明（阶段 A 把关节轴改成身体坐标系、重做预设），但要在 commit message 里写清理由。

## 8. 已知问题 / 注意事项

- 关节人偶是分块网格，髋、肩大角度旋转会露缝——手办本身的特性，不是 bug。
- 手指 15×2 根骨头有权重但没有滑条；Spine2 权重极少，弯腰靠 Spine1。
- `tall/small/broad/slim` 现在是 male 按身高/围度拉伸，真实体型模型等阶段 I 从 `_assets_src/` 派生。
- 导出视频（阶段 G）只支持 Chrome/Edge（WebCodecs）。
- 步态只在矢状面解 IK：直线上不打滑，急转弯路径上支撑脚会有少量滑动；跑步没有腾空上抬（骨盆只按可达高度下沉）。
- 步态与群众成员按组的速度 / 缩放计算；成员各自的缩放差异只影响相位，不单独调整步幅。
- "生成画布节点"（导出的视频接回 CanvasFlow 画布）和"虚拟相机（手机扫码手持录运镜）"是另两条线，不在本路线内；后者本质是从外部喂一串机位关键帧，阶段 C 的接口能接。
- 时间轴面板只列出有动画数据的实体；没有动画的实体要先在 Inspector 点 ◇ 才出现在面板里。
- active 期间在 Inspector 输入框里逐字输入时画面实时变化，但只在 change（回车 / 失焦）时归属一次；播放中拖轴标签会被逐帧求值覆盖（gizmo 拖动会自动暂停，面板输入不会）。
- 环绕三参数是会话态（`app.pathMeta`），刷新页面 / 拖过顶点后退化为普通点集，编辑框消失——有意为之（生成器参数不进文档）。
- orient=tangent 的路径在 t=start 把朝向换成首段切线：位置不跳，但若角色原朝向与首段方向不同，开始那一刻会转身（选 keep 可保留手动朝向）。
- 顶点拖动在顶点所在的水平面上进行（路径点同高），不支持拖高度；路径不能吸附到其他路径、不能调曲线张力、不能分段调速（任务说明列为不做）。
- 顶点球优先于 gizmo：首个顶点与角色脚下的 gizmo 中心重合，点中顶点时拖的是顶点（gizmo 三轴仍可用）。
- 手绘首点被替换为实体当前位置：若从远离角色的地方开始画，开头会有一段从角色连过去的线。
- 拖键 / 删多键是逐个调用 removeKey / setKey，每次都整份校验；几百个键一起拖会有可感知的停顿（100 键内无感）。
- 竞品参考：liblib.tv 导演台。实测要点：一句话生成整场景（含编组、路径、半环绕运镜、天空）；AI 识图导入站位；24 个姿势预设；轨道为 位置/旋转（角色）、位置/焦点/视角（机位）；路径蓝线球形顶点可拖；播放时角色切走路。
