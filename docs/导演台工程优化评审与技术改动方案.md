- **导演构图旧断言已过时**：全量回归发现 director 仍要求脚底约 43%，但最新默认机位与 defaultview 已明确要求约 63%（位置 [0,2.2,10]、注视 [0,1.2,0]、FOV 50）。在独立原始提交副本复现同一失败后，更新 director 断言并增加精确机位/导演视角一致性检查；不回改产品构图。
- **路径编辑预览不能存入恢复点**：保留 `loadingDocument || pathEditor.drag` 延后保存的防线；继续只订阅已提交历史事件。新恢复流程同样走 `loadSceneText` 与原子文档加载，保留 editorView.fov、三维路径、停留时序和撤销合同。
- **异步恢复不抢场景**：用持续可见的恢复入口列出会话快照及时间；读取完成只提供候选，不自动加载。新建编辑可存入自己的会话记录；恢复候选不可因后台清理丢失。按会话保留一份最新快照；只清理用户明确处理的记录，不按全局 revision 比大小。
- **迁移事务与标记一起提交**：旧键验证通过后，以固定 legacy 记录及数据库内迁移标记原子写入；首次发布保留旧 localStorage 键。坏记录不阻断启动，存储不可用仍允许编辑和导出。
- **导出保留新路径取消逻辑**：保留 `pathEditor.cancel()`；将编码 flush 放在同一个导出会话内，避免最后一帧之后提前恢复场景。取消时主动关闭编码器，守卫输出回调和封装，处理 flush 拒绝，不仅做 Promise.race。
- **CI 必跑包括新增功能**：PR/main 每次运行 default、doc、ai、store、revision5、pathselect、motion、defaultview、director 及新增保存回归；export 在 PR/main 均跑以免漏掉间接渲染依赖。固定 Chrome for Testing 与 Linux 中文字体，等待字体 ready。全量作业逐套件留报告；姿势变更在同一浏览器/字体环境比较基线修订与当前修订，不采用 macOS 静态像素基线。
- **验证范围如实记录**：本地可验证命令、失败退出码和依赖配置；GitHub 实际运行、Pages 部署阻断和分支保护无法由本地绿灯证明，交付时单独说明。

## 1 结论与取舍

本文优先级定义：P1 为下一批实施；P2 为第一批稳定后实施；P3 为出现明确需求或测量证据后启动。当前没有证据支持将六项优化统一定义为紧急 P0。

| 外部建议 | 结论 | 优先级及实际处理方式 |
| --- | --- | --- |
| E2E 接入 CI | 采纳 | P1。补 PR 检查和主分支发布前检查，固定浏览器环境；先处理已有测试失败。 |
| 拆分 Three.js 与业务包 | 采纳，但修正收益预期 | P2。主要提升更新后的缓存复用，不能把入口变小等同于首屏传输大幅降低。 |
| 全量改具名导入或新增 `src/three.js` 门面 | 不作为优化任务 | 当前工具链支持对静态命名空间引用摇树；本地对照试验无体积差异。根目录门面还会触发现有分层限制。 |
| 顺手升级 Three.js | 暂缓 | P3，独立兼容性项目。当前导出有明确依赖 r160 的颜色处理逻辑。 |
| 压缩两个素体 GLB | 采纳方向 | P2。必须保持骨骼语义、姿势、贴地和旧文档兼容，先试验后替换。 |
| 所有 public 资产直接改成哈希 URL | 部分采纳 | P2。角色模型可先做；全景图需要稳定文档引用到运行时 URL 的映射，不能全局字符串替换。 |
| 视频导出改 Worker | 暂缓 | P3。先补取消边界和测量，再决定是否拆编码或整套渲染。 |
| 导出每帧让出主线程 | 已有，无须重复实现 | 当前 `renderFrames()` 每帧 `setTimeout(0)`，另有进度、取消和编码背压。 |
| Safari 和 Firefox 加 MediaRecorder WebM 兜底 | 当前不做 | 这是另一种导出模式，不能直接替代现有离线逐帧、固定时长的 MP4 合同。先做能力检测和明确提示。 |
| 群众直接替换为 InstancedMesh | 当前不做 | P3。普通实例化不能保留独立骨骼姿势和现有解组行为；先测量角色数量与实际瓶颈。 |
| 自动保存换 IndexedDB | 采纳 | P1。第一版只换存储层，保留可携带的场景 JSON；同时补状态、失败提示和旧存档迁移。 |
| 增量类型检查 | 采纳 | P2。从纯逻辑和边界类型开始，保留 JS，不全仓重写。 |
| AI SSE 流式 | 暂缓 | P3。先细化现有状态反馈；有明显等待体验需求时再做完整链路。 |
| AI 增加只读查询 | 有条件采纳 | P2 先修摘要截断和目标上下文；复杂大场景再增加有界只读查询，不强制每次两轮模型调用。 |
| 迁移测试 | 采纳 | P2。当前迁移表为空，先测当前契约；真正升级 schema 时再补旧版本 golden fixture。 |
| 性能回归门 | 采纳测量，暂缓硬阈值 | P2。按角色、道具、轨道、导出分开测；不要用共享 CI 的单个 FPS 数字决定发布。 |
| 全量中文文案集中为 messages 表 | 当前不做 | P3。没有明确多语言需求时收益有限；AI 协议词汇也不能和展示翻译混为一张表。 |
| 不换 React 或 Next，不急着建账号后台，保留 ops | 采纳 | 沿用现有技术路线；这些架构调整不属于本轮工程优化。 |

## 2 需要纠正的事实

### 2.1 自动保存有大小提示，但写入异常不可见

`src/app/SceneFile.js` 的 `AutoSave.save()` 在文档超过 4 MiB 时已提示“场景含大图，未自动保存，请手动导出”。因此“超限总是静默放弃”不成立。真正的问题是 `localStorage.setItem()` 抛错后只调用 `console.warn`，用户看不到当前场景没有保存成功；同时没有持续可见的保存状态。

IndexedDB 适合存较大的结构化文档，但配额取决于浏览器、磁盘和站点状态，不能承诺固定几百 MB 或永不丢失。仍须处理配额不足、存储不可用和失败恢复。[浏览器存储配额说明](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)

### 2.2 视频导出已有协作式让出和背压

`src/app/VideoExporter.js` 已具备：每帧让出、进度通知、AbortSignal 取消、队列大于 4 时等待、VideoFrame 关闭、会话状态恢复。编码使用异步 WebCodecs API，“240 帧连续同步阻塞”不是对当前实现的准确描述。

仍在主线程的工作包括时间轴求值、渲染、像素读取和翻转。后台标签页可能减慢调度，但帧时间戳由 `i / fps` 决定，减速不能直接推导出文件时序错误。当前背压等待内部没有检查取消，最后的 `flush()` 等待也应核查取消路径，这是比全面 Worker 化更小、更明确的改动。

已有 WebGL 上下文的主画布不能简单调用 `transferControlToOffscreen()` 移交；要做 Worker 渲染，需要独立的画布、渲染器及可在 Worker 中重建的场景与资源生命周期。[OffscreenCanvas 转移限制](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/transferControlToOffscreen)

### 2.3 群众入口已经限制行列数

`src/doc/edit.js` 的 `CROWD_LIMITS.size` 是 `[1, 6]`，公共创建入口夹取行列，AI 校验复用同一范围。当前不是可直接从该入口创建 10×10。

这不代表不存在规模问题：多个 6×6 群众、导入的大组和多个独立角色仍可能增加负载。群众成员支持独立骨骼、名字、颜色、序列化和解组，不能视为完全相同的静态道具。

### 2.4 AI 已有场景读取与等待反馈

`src/ai/apply.js` 的 `summarize()` 已提供实体名字、位置、姿势、机位、路径、约束与关键帧摘要；`src/ui/AiPanel.js` 已显示运行状态、尝试次数并支持取消。因此“只有写路径”“完全没有反馈”都过于绝对。

实际缺口是摘要最多列出 60 个顶层实体，组成员名字最多显示 8 个，且不包含所有路径点和关键帧值。改进重点应是让目标实体的有效信息进入上下文，而不是先引入强制 plan → ops 两轮调用。

### 2.5 测试数量和像素阈值不能直接照搬

本地已有 20 个单测文件。交接核对时，E2E 入口已登记 21 个套件，包含并行工作新增的 `motion`。`npm run test:e2e` 只运行 `default`，不等于运行全部回归。

`posediff` 是独立比较工具，默认差异占比阈值为 0.001；`doc` 和导出帧对比使用 0.005。`all` 不会自动完成“生成姿势基线再调用 posediff”。不能只添加一条 E2E 命令，就宣称所有视觉回归已进 CI。

此外，`e2e/suites/tl.mjs` 已有 100 键、10 条轨道播放的长任务检查。性能测试应扩展现有覆盖，而非从“完全没有”出发另建一套。

### A2 自动保存改为异步可靠存储

范围：`src/app/SceneFile.js`、`src/main.js`，新增 `src/app/AutosaveRepository.js` 与轻量保存状态 UI；新增单测和真实浏览器恢复测试。

第一版使用 IndexedDB 保存完整场景 JSON，保留现有 `director-stage/0.1` 文档格式和 dataURL。暂不引入图片 Blob 拆分、项目管理或云同步，避免把存储改造变成资源协议重构。

建议存储合同：`readRecovery()`、`writeSnapshot(snapshot)`、`clearRecovery(id)`。记录包含存储格式版本、场景文本、保存时间、会话标识及会话内序号；存储格式版本独立于场景 schema。仅在 IndexedDB 事务完成后宣布保存成功。

核心行为：

1. 延续已提交历史变化后 1 秒防抖，不保存拖动中的临时预览；覆盖记录、撤销、重做与成功导入。启动 reset 不产生存档。
2. 同会话最多一个写事务在途，期间发生多次修改只保留最新待写快照；旧请求不得在新请求之后覆盖它。序号仅用于同会话排序，不能把不同页面的 `store.revision` 当成全局版本号。
3. 状态至少区分“有未保存修改”“正在保存”“已保存于某时刻”“保存失败”。写入成功时若仍有更新排队，不能显示全部已保存。
4. 配额、数据库打开失败、事务中断、序列化失败均显示可恢复错误及“导出场景”入口。失败保留最后一次成功快照；后续重试成功可恢复正常状态。
5. 启动时先取得可恢复存档再允许新会话覆盖。异步读取完成时不能突然替换用户已经编辑的场景；沿用主动点击恢复，并为开始新场景提供明确选择。
6. 跨标签页至少做到不静默覆盖其他会话的恢复点。建议按会话存有限数量快照，恢复界面显示时间；只在新快照成功后清理旧记录，保留尚未处理的恢复候选。无需实现实时协作或锁管理系统。
7. 旧 `director-stage:autosave` 读取后经过 JSON 解析、`migrate()`、`validate()`；只有新存储写入成功后才记迁移完成。首次发布保留旧键作为回退，不继续双写；损坏旧记录不得导致应用启动失败。
8. 页面隐藏时可以尝试提前提交待保存数据，但不能把 `beforeunload` 的异步写入视为保证。未完成保存时状态必须准确。

验收用例：小场景及含有效 2:1 大图、序列化体积超过 4 MiB 的场景均可保存并刷新恢复；连续编辑、撤销重做、写入中再次编辑不会倒退；模拟配额和事务错误后仍能导出；旧存档只迁移一次；损坏记录可跳过；启动读取与新编辑不会互相覆盖；两个标签页的恢复点不互相静默替换。

测试层次：单测检查队列、状态和迁移决策；真实浏览器检查 IndexedDB 持久化、刷新和用户恢复流程。资源依然走原有场景校验和原子加载。

### A3 补齐导出取消边界

范围：`src/app/VideoExporter.js`、`src/ui/ExportModal.js` 及导出测试。

保留现有逐帧离线实现。背压等待中检查 AbortSignal；最终编码 flush 等待应能响应取消；处理取消与编码器错误同时发生的情况，确保只清理一次且没有未处理的 Promise 拒绝。不能仅用 `Promise.race` 返回后任由编码和封装继续运行。

成功、错误和取消均必须恢复主渲染、播放头、名牌、洁净渲染状态和 UI；取消不下载文件。若显示后台标签页提示，应说明“切到后台可能延长导出时间”，不要声称必然导致文件损坏。

验收：保留已有普通取消测试，增加编码队列积压时取消、flush 阶段取消和编码器报错；取消后不继续提交新帧，不残留锁定 UI；文档和撤销栈不变；正常导出仍满足帧数、时长、方向、色彩与确定性检查。

## 5 第二批实施任务

### B1 分包与构建报告

范围：`vite.config.js`、构建体积报告脚本、生产构建冒烟测试。

将 Three.js 及其 examples 依赖收敛到一个 vendor chunk；Immer 是否单独拆分以产物依赖图确认。保持 `ExportModal` 的动态导入，首屏不得静态加载 VideoExporter 或 mp4-muxer。参考本次试验采用按包路径判断的 `manualChunks`，不要把所有 node_modules 强行合并进同一 vendor。[Rollup 手动分包说明](https://rollupjs.org/configuration-options/#output-manualchunks)

新增报告记录原始字节、gzip、首屏静态依赖合计、延迟块大小及重复 Three 实例。只改业务文案时检查 vendor 内容及文件名保持稳定。做生产构建下的真实加载和首次导出测试：当前不少 E2E 从 `/src/...` 动态导入模块，不能只设置 `TEST_URL` 就假定它们适用于 dist。

验收：开发和生产都正常；Three 不重复打包；延迟边界不被破坏；业务变化不会无故使 vendor 失效。不得仅凭“入口小于 500 kB”宣布首屏优化成功。

### B2 模型压缩与资源版本

范围：角色 GLB、`src/rig/profiles/index.js`、资源构建脚本、必要的运行时 URL 解析模块。

先对两个素体各做一份候选产物，记录工具版本、参数、源文件哈希、输出字节与加载时间。使用当前 r160 解码器能读取的扩展，不因工具默认参数变化输出未经验证的新扩展。

gltfpack 不只是压缩字节，它可能量化几何、合并网格和裁剪节点。对本项目要保留被骨骼档案引用的名字和变换语义，检查皮肤权重、关节映射、逆绑定矩阵、包围盒和脚底采样。可评估保留命名节点等选项，但命令参数不能代替加载后验收。[gltfpack 官方说明](https://github.com/zeux/meshoptimizer/blob/master/gltf/README.md)

验收包含三种基础档案和派生体型、全部姿势预设、行走采样、贴地、群组解组、导入旧文件、截图与视频。压缩改变像素时记录差异来源；若无法在可接受精度内获得收益，保留原资产并提交测量报告即可，不强求体积目标。

资源 URL 分两步处理：

1. **角色模型先做。** 场景通过 `body`、`profile` 重建角色，运行时模型 URL 可改为 Vite 管理的哈希资源。确认开发校准页、Node 单测和分层检查仍可运行；不要直接往被 Node 单测导入的纯配置模块塞入未经处理的 `.glb?url` 导入。
2. **全景资源后做。** `schema.js` 只接受 `./assets/` 下的路径，禁止查询串；`Panorama` 会把路径写回文档。保留文档里的稳定逻辑路径，在加载边界将已知内置路径映射到当前哈希 URL；dataURL 原样处理。旧导出文件必须仍可加载。不要把本次发布的物理哈希文件名持久化为长期文档引用，也不要放宽为任意远程 URL。

Vite 会给参与构建的导入资源生成哈希名，public 文件则原样复制。固定文件名存在缓存一致性风险，但是否读到旧内容仍与 HTTP 缓存策略有关，不能称为“永远无法失效”。[Vite 静态资源规则](https://vite.dev/guide/assets.html)

验收：在非根路径部署也能加载；改动资产内容后请求 URL 改变；未改资产 URL 稳定；旧 JSON 导入正常；截图不受跨域污染；无重复打包的同一模型。资产压缩与 URL 改造分别提交，以便定位回归。

### B3 增量类型与迁移合同测试

范围：类型检查配置、脚本及首批纯逻辑模块，`src/doc/migrate.js` 的测试。

保留 JS，使用 JSDoc 和增量 `@ts-check`。首批选独立数学函数、导出规格、文档结构及 Provider 的输入输出边界，建立 `SceneDocument`、ops 和快照存储的可复用类型。类型不替代运行时校验。

先通过有限入口试点，再扩大覆盖。不要同时全仓 `checkJs: true`、又宣称只检查几个目录；被导入的源码也可能进入类型程序，须记录实际覆盖范围。禁止用大面积 `any`、`@ts-ignore` 或关闭关键检查制造通过；配置确实通过后再加入必跑 CI。

迁移表目前没有真实旧版本步骤，先测当前版本深拷贝、入参不变、原始值处理、未知版本被后续校验拒绝、当前旧文件缺可选字段仍兼容。未来增加迁移时，每一步必须提供真实旧文档 fixture，验证迁移后可校验、可加载、语义保留和再次迁移幂等；不为增加测试而虚构产品从未支持过的版本。

### B4 性能测量与大场景上下文

性能场景分别覆盖：典型少量角色、单个 6×6 群众、多个群众、200 个几何道具、密集轨道以及 720p/1080p 导出。记录资产加载到首帧时间、时间轴求值、主线程长任务、渲染调用数、内存趋势和每秒导出帧数，避免把不同成本的“200 实体”当成同一种负载。

编辑器是按需渲染，静止场景没有稳定连续 FPS；应分别测首次交互、连续拖动和播放。区分桌面 GPU 与 CI SwiftShader；先收集多次基线，报告中位数与高分位，再在固定环境选择合理阈值。第一版性能作业只报告，新出现资源泄漏、无限队列等确定性错误仍须阻断。

AI 上下文先做有界增强：保留全局结构概览，在字符预算内优先包含选中对象和名字明确命中的目标、关联机位、路径及约束。测试用户操作第 61 个实体、组中第 9 个成员名、长路径和关键帧值时的信息完整性。超出预算时明确指出摘要被裁剪；不能默默省略目标后仍让模型猜测。

增加只读工具前，先用固定任务集比较目标解析正确率、首轮校验通过率、修正轮数、耗时和上下文长度。只有上下文增强仍不足时再增加实体详情查询，限制返回字段和调用次数；仍通过原来的 ops 原子应用路径提交。

代码审阅另发现一项值得先补的 AI 边界：请求发出时的摘要和响应应用时的文档可能不同。`AiAgent.run()` 未显式保存请求起点的 revision，且取消检查主要在 Provider 内。增加“等待期间用户改场景”和“响应后资源准备期间取消”的针对性测试；确认缺口后，将起始 revision 与取消信号检查贯穿到提交前。已有资源加载版本检查继续保留，不把这项扩展成新的 Agent 架构。

| 全量国际化 | 明确推出另一种语言 | UI 翻译与 ops 枚举、文档字段、AI 词汇分离。 |
| 后端与账号 | 明确协作、项目共享或统一代理需求 | 保留现有本地使用路径，另行定义身份、存储和访问模型。 |
